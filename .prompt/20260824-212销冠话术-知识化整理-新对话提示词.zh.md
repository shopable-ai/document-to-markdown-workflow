## 任务拆分

### 1. 本地清单和重复检测

- 通过一次本地脚本递归读取 389 个 Markdown；不要把全文打印回 Codex 对话。
- 生成来源索引、正文规模、标题结构、图片引用、精确重复、规范化重复和跨文档重复段落报告。
- 每个文件必须进入 `processed`、`unclassified` 或 `needs-review` 中的一种明确状态，禁止静默丢弃。

### 2. 建立多维分类体系

- 销售阶段建议覆盖：开场破冰、关系建立、需求发现、资格判断、价值呈现、产品演示、异议处理、报价议价、成交推进、跟进复购、客服售后。
- 渠道建议覆盖：电话、面谈/门店、线上沟通、邀约、回访。
- 行业、客户意图、异议类型、销售方法和风险使用独立标签，不要把所有维度硬塞进单一目录树。
- 分类体系应由语料统计校正，最终保持 8–20 个一级主题；无法判断的内容必须有明确原因。

### 3. 去重并生成知识单元

- 原始 Markdown 永不去重或删除；只在派生知识层合并重复内容。
- 完全相同内容生成一个 canonical ID，所有来源都保留为成员引用。
- 相似内容不得仅凭标题合并；必须有正文证据，并保留冲突版本。
- “综合话术”可以由 AI 生成，但必须标记 `canonical-synthesis`，并引用支持它的原始单元；不得伪装成原文。
- 对欺骗、强压、过时承诺、金融/医疗/法律敏感表达增加风险标签，不把它们直接包装成推荐话术。

### 4. 生成可用成果

- `00-总目录.md` 提供按销售阶段、渠道、行业、异议和来源的入口。
- `主题库/` 形成面向阅读者的主题手册。
- `话术卡片/` 形成适合检索、RAG 或客服/销售辅助系统使用的小型独立单元。
- `索引/` 必须支持从来源追到知识单元，也能从知识单元追回来源。
- 先生成三个代表性主题的试产物并运行结构/来源校验；通过后自动完成全量，不等待无必要的人工确认。

### 5. 完整验收

- 重新计算输入树哈希，证明输入未变。
- 对 389 个来源、全部知识单元、全部 Markdown 链接和全部来源引用运行独立验证。
- 检查空文件、重复 ID、悬空来源、无来源综合内容、静默丢失和分类覆盖。
- 将详细结果写入报告；对话只返回汇总、失败项和最终路径。
- 每次测试记录结果；发现问题后重新梳理原始需求、实现范围和验收标准，修正并复测，直到验收证据成立。
