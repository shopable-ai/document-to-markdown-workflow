## 格式专用真实链路

### PPTX

- A1/A2 必须真实读取 OOXML：每页文本、段落、形状、图片、分组、连接线、对象 ID、坐标、父子层级、z-order、媒体关系和主题/母版信息。
- A3 的页面图必须来自 PPTX 自己的真实渲染，不能直接拿无关 PDF 或 fixture 页面图替代。
- 优先使用可复核的本机 Office 渲染器（例如 `soffice`/项目注册的 `office-page-renderer`）；记录命令、版本、退出码和渲染失败原因。
- 诊断字体缺失、字体替代、文本溢出、错位和连接线错乱：记录主题字体、每个使用字体、`fc-match`/系统字体匹配结果、渲染警告和影响页码。字体诊断只能说明风险，不能把原生 XML 事实改写成渲染猜测。
- `ppt/media` 中实际被目标页面引用的嵌入媒体必须复制到 `assets/embedded/`，并登记来源页码、对象 ID 和 SHA-256。

### PDF

- A1/A2 必须真实读取 PDF 文本层和布局：文本块、阅读顺序、bbox、字号估计、页尺寸、字符/图片/线/矩形统计。
- A3 页面图必须来自原始 PDF 页面渲染；不能把 PPTX 渲染结果当成 PDF 页面证据。
- PDF 的页面布局是视觉事实来源；不要为了“统一格式”用 PPTX XML 去覆盖 PDF 的阅读顺序或排版。

### 图片

- 若后续输入是 PNG/JPG/JPEG，保留原图作为页面资产，运行本地 OCR/视觉复核，并明确没有原生结构层；不要虚构坐标或节点。

## 来源候选比较规则

- 只有当用户显式提供同一逻辑文档的多个候选（例如同名 PPTX 与 PDF）时，才运行本地大模型进行“来源候选比较”。比较维度必须至少包括：文字覆盖、字体/换行、裁切、页面排版、图形/连线关系、图片清晰度、渲染异常。
- 比较结果必须是结构化 JSON，记录候选文件、页数、输入资产、模型、时间、维度结论、选择理由和不确定项；不能用关键词数量或 HTTP 200 代替视觉比较。
- `preferred_source` 只能在同源候选间产生。上面两个实际输入必须分别生成两个 package：
  - `18个工作思维模型.pptx`：PPTX XML + PPTX 自身渲染为事实；
  - `21个成长思维模型.pdf`：PDF 文本层 + PDF 自身渲染为事实。
- 如果没有候选比较对象，报告写 `source_selection: single-source`，不要伪造“PPT 优于 PDF”的结论。

## 视觉复核和内容分类

1. 原生提取完成后，先只读检查 `ssh mac96` 的连通性、服务和实际视觉模型标识。
2. mac96 可用时，对每页或必要复杂页面资产实际发送请求，要求只返回可解析 JSON。记录目标、模型、输入资产、请求时间、状态、关系结论、分类结论和不确定项。HTTP 200、模型列表、非空响应或关键词出现都不算视觉复核成功。
3. mac96 不可达、超时、模型不支持或输出不可解析时，才运行本机 Apple Vision OCR；记录引擎、语言、版本、fallback 原因和候选置信度。
4. 两者均失败，或关系/分类仍无法裁决时，保留页面原图并进入 `needs-review`；不得用手工样例补齐。
5. 整页图足够表达复杂关系时，不要额外创建截图；`assets/regions/` 保持空目录是合法结果。只有整页图不足以支撑某个局部复核时才创建区域资产，并登记裁剪坐标和父页面资产。

内容分类必须把视觉层级与语义层级分开保存。对于页面中类似：

```text
人活着其实就两件事
搞定自己、搞定别人
```

应判定为“页面标题”和“标题下的对比/主题内容”，不能把两者拼成一个标题。分类依据至少保留：原生 bbox、字号/字号估计、顶部比例、水平区域、段落/形状关系、`vs`/并列等语义标记，以及 mac96/OCR 的候选支持。工程证据放入 `evidence/` 和报告，读者-facing `document.md` 只保留整理后的语义。
