# 知识地图转 Markdown

先逐张地图纵向完成转换，再扩大规模。保留图片实际包含的内容；不要用泛泛的解释替代密集的实体/Logo 矩阵。

## 必需的输出契约

在用户选择的来源/结果根目录下使用以下布局：

```text
AI知识库_转换结果/
├── 最终知识库/
│   ├── <map-title>.md
│   └── assets/<map-title>.<image-ext>
├── _过程文件/<source-id>/<map-id>/...
├── _过程文件/按标题索引/<map-title>__<sha8> -> ../<source-id>/<map-id>
├── _过程文件/按来源索引/<source-title>__<sha8>/<map-title>__<sha8> -> ...
├── _过程文件/目录索引.md
└── 运行记录/
    ├── ledger.jsonl
    ├── summary.md
    ├── duplicate_decisions_latest.json
    ├── 重复内容决策索引.md
    └── 继续执行前必读.md
```

将 `最终知识库/*.md` 及其相对路径图片资产视为唯一面向用户/AI 的结果。OCR、模型响应、清单、裁剪图、JSON 和日志都放在 `_过程文件` 下；不得要求使用者依赖它们才能使用最终 Markdown。规范的过程目录可以使用哈希以便稳定地恢复和去重，但每张已完成或已终止的地图还必须能通过面向人的标题/来源索引访问，并列在 `_过程文件/目录索引.md` 中。

最终文档从 `assets/final-knowledge-map-template.md` 开始创建。

## 工作流

1. 只发现已完成的归档文件。跳过 `.downloading`、`.part`、`.crdownload`、不完整或仍在变化的文件，并记录 `skipped_partial`。
2. 计算归档文件和地图图片的哈希。在任何 OCR/VLM、唯一地图归属或相似性处理之前，从追加式 ledger 重建 `运行记录/duplicate_decisions_latest.json`，并针对新清单运行重复项预检。完全相同的 SHA-256 重复项可以复用之前成功的结果，同时创建新的来源出现清单和 ledger 记录。感知相似性只能作为待复核候选，不能证明身份；决定转录、替代或补缺之前，必须应用下方的版本仲裁政策。
3. 安全地提取到 `_过程文件`；拒绝路径穿越、绝对路径、符号链接、特殊文件、过深目录或过度扩展。
4. 在选择试点或运行昂贵的 OCR/VLM 之前，为每一张其他方面属于新内容的图片执行语义资格门禁。图片扩展名本身不能证明文件应转换为知识库 Markdown。如果可见内容没有需要保留的知识地图语义，例如装饰照片、聊天/营销截图、课程/文章页面、封面、海报，或不含可复用分类/实体结构的示例图片，则在阶段 `non_map_no_semantic_payload` 记录为 `blocked_unsupported`，在其来源清单中设置 `no_rerun: true`，创建来源/标题过程条目，然后跳过转换。不要将它复制到最终资产，也不要创建最终 Markdown 页面。只进行确认这一点所需的最低限度视觉检查；不要运行高精度 OCR/VLM。如果确实无法确定是否存在有意义的结构化语义，应将项目保留在范围内待复核，而不是猜测。
5. 只选择一张语义合格的代表性地图进行逐图试点。在其最终 Markdown 通过下方门禁之前，不得开始批量转换。
6. 将原始图片保存在 `最终知识库/assets/`，并使用符合 CommonMark 的相对图片路径嵌入。目标路径始终用尖括号包裹，例如 `![标题](<assets/标题 含空格.jpg>)`，这样包含空格或非 ASCII 字符的文件名也能可靠渲染。
7. 全局分析布局，识别每一个可见的分类/容器。
8. 按原始分辨率裁剪每个分类。在全局图、分块图和分类裁剪图上运行 Apple Vision OCR；候选项和坐标只作为过程证据保留。
9. 对包含大量 Logo/实体的分类，提取每一个可见的供应商/平台/实体。使用定向 VLM 调用将图片像素与 OCR 候选项相互校对；不要把泛化的整图摘要当作供应商列表。
10. 在结构化发布之前建立稳定的行清单。为每一条共识 OCR 行赋予 `line_id`，保留所有支持它的 `region_id` 值，并登记每一项关键的双路径分歧。要求定向视觉 JSON 将每一段可见的语义文本标记为已映射、OCR 重复、非语义来源说明、不可读、冲突，或明确引用另一个已复核区域的边界重叠。一个 OCR 行可能包含多个视觉上不同的节点；此时多个节点可以引用同一个 `line_id`，但每个节点都必须拥有自己的、彼此不重叠的逐字证据范围。同一来源范围也可能出现在重叠裁剪图中；按出现层面的并集验证一次，保留所有贡献 `region_id`，不要把裁剪重复误认为第二个实体。绝不要强行采用一行对应一个节点的映射。模型声称自己已完整提取并不是证据；运行本地行与范围覆盖检查，并保留其报告。
11. 从可见的来源实体到最终节点构建 `source_to_final_trace.json`。每一个可见的语义实体都必须映射到输出，或成为明确的 `†`/`needs_review` 项；每一个关键冲突都必须有第二来源或定向裁剪复核。即使 OCR 数量、HTTP 状态或模型摘要看起来正常，缺少行 ID、重复分配、未映射关键区域或未登记冲突也会使来源保真门禁失败。
12. 当视觉传输、模型、模式或提示词发生变化时，在一张已验收地图和一张无结构的高密度地图上进行校准。将结构化 JSON 与现有 OCR/trace 证据比较，并重复执行一次确定性请求。将文本范围覆盖和视觉分类作为独立门禁测试：响应可能覆盖每个字符，却遗漏标题、一级分类、父级链接或必需的 JSON 字段。本地新增的 ID、区域默认值或角色可以规范表示，但不得伪造缺失的视觉分类结论。如果校准静默遗漏节点、产生无效证据映射、缺少有证据支持的分类字段，或无法复现，就不得扩大规模。只通过已经验证的私有端点传输必要的图片/裁剪图；不要复制来源归档或在远端留下图片文件，且绝不要在日志中暴露端点凭据。
13. 对含义不明确的艺术化 Logo 进行视觉复核。联网搜索只能用于核对拼写或发布来源；优先使用原始/官方来源或同期来源。绝不要添加源图片中不可见的实体。
14. 编写独立的 Markdown，其中包含嵌入图片、完整分类体系、按分类划分的实体列表、时间范围和明确的不确定性标记。
15. 使用 `scripts/update_ledger.py` 记录结果；每张地图或每个已接受的终止批次完成后，重建 `summary.md`、重复决策索引和面向人的过程索引。
16. 只有在所有必需成员都成功且归档门禁通过后，才能移动原始归档文件。否则将其留在原处。

## 完全重复、近似重复和年度版本

不要为相同内容重复投入高精度 OCR/视觉工作。必须区分精确身份与视觉/内容相似性：

1. **完全相同的 SHA-256 重复项**：复用现有的最终 Markdown、资产、OCR/裁剪图和复核证据。为每个归档创建过程目录，内含相对证据链接、来源专用清单，以及阶段为 `hash_deduplicated` 的 `success` ledger 出现记录。
2. **近似重复候选项**：感知哈希、SSIM、图片嵌入、文件名相似性和布局相似性可以提名一对候选项，但不能授权复用。在全局和分类层面比较原始分辨率图片：可见分类名称、主要实体列表、日期、版本标签、发布者/来源和图片清晰度。
3. **较新版本等价或严格包含旧版本**：优先将较新/更清晰的版本作为面向 AI 的规范结果。对于 B17 年度地图，经过验证的 2020 版本通常优先于内容等价的 2019 版本成为规范候选，但文件名中的年份或归档成员时间戳本身不是充分证据。不要高精度转录旧版本。在 `_过程文件` 下保存相似性/差异复核；将旧版本出现记录为阶段 `superseded_near_duplicate` 的 `blocked_unsupported`，并在 `notes` 中写入规范地图 ID/路径。如果旧结果已经发布，保留其可恢复性并标记为已替代；不要静默删除。
4. **旧版本包含独有的可见内容**：只完整恢复规范/较新版本。对旧图片执行低成本补缺审计，然后仅将其独有的可见分类/实体加入来源标注清晰的历史补充中；如果这样更清晰，也可以创建一个小型补充 Markdown。如果使用了旧版本的独有内容，必须保留旧原图。将旧版本出现记录为阶段 `gap_fill_published` 的 `success`；不要重新创建共享内容。
5. **版本之间存在冲突**：保留带时间标记的差异，不要用一个版本覆盖另一个版本。如果比较结论不明确，使用 `needs_review` 或 `failed_retryable`，并分开保留图片。

每一个相似性决策都必须留下过程证据，其中包括：比较的 SHA-256 值、相似性方法/分数、分类层面的重叠、各版本的独有项目、选定的规范版本及其理由。绝不能仅凭相似性阈值合并或丢弃内容。

## 跨对话重复项无操作门禁

追加式 ledger 是权威来源；`duplicate_decisions_latest.json` 是可派生、可重建的执行索引。在新对话中恢复工作时，此门禁是强制性的：

```bash
python3 scripts/rebuild_duplicate_decision_index.py \
  --result-root '<root>/AI知识库_转换结果'

python3 scripts/check_duplicate_decisions.py \
  --registry '<root>/AI知识库_转换结果/运行记录/duplicate_decisions_latest.json' \
  --inventory '<path/to/new-inventory.json>' \
  --output '<root>/AI知识库_转换结果/_过程文件/<batch>/duplicate_preflight.json'
```

在分配归属之前解释预检结果：

- `reuse_exact`、`reuse_exact_existing_content` 或 `reuse_existing_terminal_result`：不要再次 OCR。复用规范结果/证据，只创建缺失的来源出现记录、清单、语义条目和 ledger 记录。
- `skip_superseded`、`skip_existing_terminal_identity` 或 `skip_exact_existing_terminal_content`：如果该出现记录已经存在则不执行任何操作；否则只补充缺失的出现元数据。不要重复高精度 OCR/VLM。最后一种状态覆盖同一终止内容 SHA 出现在不同归档中的情况。
- `reuse_published_gap_fill`：复用已有的规范结果和补充内容；绝不要重新生成共享内容。
- `resume_similarity_review_only`：只恢复缺失的可见比较证据。这不是进行完整转录的许可。
- `new_unregistered_identity`：继续进行精确资产/ledger 查找和可见相似性提名。这不能证明地图是唯一的。

只有在来源 SHA 发生变化、其证据无法修复、规范结果缺失/损坏且无法重新链接，或用户明确要求重新仲裁时，才能重新打开已经确认的重复决策。新对话、新归档路径、文件名变化或更新的扫描版本，都不足以成为重新运行的理由。

## 最终 Markdown 门禁

状态设为 `success` 前必须通过所有门禁：

- 相对图片链接能在磁盘上解析，且兼容 CommonMark 的渲染器会为其输出 `<img>` 元素；包含空格的原始目标路径不通过。
- 当结果通过知识库运行时提供服务时，重建其页面/链接索引，并验证 Markdown 路由和引用的图片都能成功返回。文件虽然存在但不在运行时索引中，不通过访问门禁。
- 每一个可见分类都有对应的 Markdown 章节。
- 每一个包含 Logo/实体的分类都有列表，或明确标记 `未识别完整，待复核`。静默遗漏不通过。
- 稳定的 OCR 行清单与视觉 JSON 具有精确的本地覆盖比较：每个输入 `line_id` 中的每个可见语义范围都在出现层面的并集中得到说明，重叠裁剪图通过链接关联而不是重复计数，多实体 OCR 行使用不重叠的逐字范围，每个可见实体都有追踪目标或明确的 `†`，且不存在未映射关键区域或未登记的关键字段冲突。
- 标题、一级分类、层级和父级链接覆盖必须独立于文本范围覆盖通过。本地确定性的模式修复不能把模型缺失的分类转换成视觉确认。
- 解释性文字只能补充来源内容，绝不能替代实体列表。
- 含义不明确的名称必须带有 `†`，并且文档要定义该标记。
- 最终 Markdown 中不得出现 `.json`、`.jsonl`、`ocr_*`、绝对过程路径或 `_过程文件` 引用。
- 必须明确历史时间范围。不能从旧地图推断当前产品声明。
- 联网研究只能核实歧义/来源，不得臆造缺失的供应商。
- 规范/补充年度版本必须说明每一项仅存在于历史版本的内容来自哪张源图片；相似性不能抹去来源信息。

当分类体系完整但一个或多个实体列表仍不确定时，使用 `needs_review`。对于工具/网络/模型失败但已有可复用上游产物的情况，使用 `failed_retryable`。只有不安全、损坏或不支持且无法继续的输入才能使用 `failed_terminal`。

## 状态 ledger

批处理前阅读 `references/run-ledger.md`。每一次尝试都追加一条记录，包括跳过和失败。绝不要改写历史；`summary.md` 反映每个归档/地图身份的最新记录。

示例：

```bash
python3 scripts/update_ledger.py record \
  --ledger '<root>/AI知识库_转换结果/运行记录/ledger.jsonl' \
  --status success --stage published \
  --source '/path/archive.zip' --archive-sha256 '<sha256>' \
  --map-id '<map-id>' --map-title '<title>' \
  --final-md '<root>/AI知识库_转换结果/最终知识库/<title>.md' \
  --category-count 36 --entity-count 519 --uncertain-count 20

python3 scripts/update_ledger.py summary \
  --ledger '<root>/AI知识库_转换结果/运行记录/ledger.jsonl' \
  --output '<root>/AI知识库_转换结果/运行记录/summary.md'
```

## 失败处理

当提取质量下降、VLM 输出无效或运行需要重试时，阅读 `references/failure-modes.md`。保留已成功生成的上游产物，并从失败阶段恢复。真实提取失败时，不要通过扩大批次来应对。
