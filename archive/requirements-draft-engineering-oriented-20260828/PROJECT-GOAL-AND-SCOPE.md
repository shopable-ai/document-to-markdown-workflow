本文件从迁移前的人类需求稿拆出长期目标和范围；它不读取代码、Workflow、测试或历史 Run 来补需求。旧需求稿已经完整保存在 archive，当前内容仍需产品负责人通过 V1 重新确认。

## 1. 要解决的问题

把当前明确提供的 PPT、PPTX、PDF、图片以及未来被批准的文档类型，整理成以 Markdown 为主体的独立交付：

- 人可以脱离原文件直接阅读和搜索；
- 文字、数字、章节、分区、表格、列表以及可确认的关系被保留；
- 流程图、图表、漏斗、矩阵、时间线等复杂视觉内容既有可搜索的 Markdown 表达，也有随包保存、正文实际引用的视觉证据；
- 看不清、无法判断或来源冲突的内容被明确标成 Unknown、needs-review 或 failed，而不是用旧材料或猜测补全。

成功不是“生成了一个 .md 文件”，而是当前来源的内容、关系、视觉证据、不确定性和来源定位能够被人复读和独立验收。

## 2. 使用者

| role_id | 使用者 | 需要得到什么 |
|---|---|---|
| ROLE-READER | Markdown 读者 | 清楚、可搜索、不过度携带工程噪声的正文 |
| ROLE-REVIEWER | 内容与视觉复核者 | 可回到当前页面或区域证据，判断已确认与未确认内容 |
| ROLE-OPERATOR | 转换执行者 | 明确来源、范围、状态、停止点、恢复点和失败原因 |
| ROLE-VALIDATOR | 独立验收者 | 事前判据、当前来源指纹、包内容和证据 |
| ROLE-DOWNSTREAM | 经明确授权的下游使用者 | 已验收 Markdown 和必要视觉资产；下游派生不得改写来源语义 |

## 3. 直接交付范围

- 当前一个来源对应一个独立 reader Markdown 包。
- 纯文本结果可以只有 index.md；需要视觉证据时才包含 assets。
- 正文使用语义标题；源文件名、页码、哈希、对象 ID 和 occurrence 放在 manifest、evidence 或正文后的独立来源说明。
- 复杂视觉的 Markdown 与图片是互补关系；任何一方不能静默替代另一方。
- 结果状态必须让人区分 passed、needs-review 和 failed，并能定位理由。

## 4. 包含的业务能力

- 当前来源识别、准入和候选关系确认；
- 文字、结构和关系的保守提取与表达；
- 简单内容和复杂视觉内容的区分；
- 必要视觉资产的提取、最小充分裁切、命名、复制和来源登记；
- Markdown 页面单元组装、分阶段修复和确定性合并；
- Unknown、冲突、失败和恢复；
- 长任务的可观察、可停止和可恢复；
- 独立验收和受限交付声明；
- 明确选择时才启用的知识库工作副本低价值整页清洗。

## 5. 非目标

| non_goal_id | 非目标 |
|---|---|
| NG-001 | 根据模板、上下文、旧示例或常识补写当前来源没有的内容 |
| NG-002 | 默认建立知识库、切分索引或把多份材料合成新理论 |
| NG-003 | 把视觉生成、翻译、改风格或重绘当成当前来源转换的默认步骤 |
| NG-004 | 因为已经生成表格、列表或 Mermaid 就删除复杂视觉证据 |
| NG-005 | 把 HTTP 成功、模型列表、队列接收、文件存在或 runner 自报完成当成内容正确 |
| NG-006 | 用 Workflow、代码、fixture 或历史 Run 反向定义本文件 |

## 6. 范围边界与 Unknown

- 多格式文件只有在本次输入中满足已确认候选关系时才比较或配对；不能仅凭相似文件名自动合并。
- 在线模型、局域网模型、原图保留和外发都受本次授权范围约束。
- 未来文档格式、模型路线和知识库后置清洗是否长期保留，继续登记为 Unknown。
- 当前 V1 为 pending-human-reconfirmation；因此本文档可以用于审查架构，但不授权真实转换或正式工程扩张。
