# 电子书格式与内容修复（Markdown 完整版 · R2 多语言与媒体策略）

## 适用范围

本规范仅修复用户明确提供、**已转换成 Markdown** 的电子书。不重新转换 PDF/EPUB，不扫描未经指定的其他文件；修复对象是有来源证据的标题、断行、列表、表格、OCR/转换残留与非正文杂质。**不翻译、不补写、不重写作者观点或缺失章节**。

运行模式必须先明确，不得把不同模式的路径和验收规则混用：

- **单本独立交付（默认）**：只处理本次指定的 Markdown，按真实书名输出可下载的 `<书名>.md`；不需要创建任何 sidecar。仅在确认不用于定位、链接或复核后可清除页面转换标记。
- **Workflow 原位修复**：仅在任务明确指定现有工作流时启用。以实际已核验的 Skill/页面单元合同为准，保留必需的 `<!-- page:N -->`、页面顺序、图片顺序、资源定位和输出路径；不能臆断工作流合同已经核验。
- **批量修复（按需）**：仅在任务明确指定目标文件清单或目录范围时启用第七、十节的范围控制、递归扫描和批量验收；不得默认扫描其他目录或套用某个历史项目的命名约定。

目标是保留作者文本、原语言、可搜索正文与已知结构关系；图片和页面定位信息按明确策略处理，而非一律删除或一律保留。

### 规则优先级与不可越过的边界（R2）

1. **保真底线最高**：不得凭猜测补字、造图表关系、变更事实、调整作者立场或无证据删正文；元信息、链接、脚注、代码、公式等有效信息不可被静默破坏。显式删图可能使信息不完整，必须如实标记，不得再声称全文信息守恒。
2. **当前运行模式的必要合同**：包括 Workflow 定位标记、输出路径、批处理范围及外部引用约束。未实际核验时视作待确认，不能自行假定冲突不存在。
3. **用户对本次任务的明确指示**：可以覆写默认图片策略、目录保留策略或授权文字体系转换；但不能隐式越过前两项。出现不可兼容冲突应暂停冲突操作、报告原因及可选处理，而非暗中更改模式。
4. **本文默认值**：保留源语言与书写体系、保留所有图片引用、优先保留不确定内容，仅修确定缺陷。
5. **语言/格式启发式**：只提供候选，不允许独自推翻上述约束。规则仅在检测到相应问题时启用。

**轻量执行参数**（在任务文字中说明即可，不强制建立配置文件）：`mode=single|workflow|batch`、`language=auto|BCP47标签`、`script_conversion=none|zh-Hans|zh-Hant`、`images=keep_all|remove_all|remove_page_images`。默认分别为 `single`、`auto`、`none`、`keep_all`。`zh-Hans`、`zh-Hant` 是目标文字体系标记，不是翻译授权；若用户仅要求翻译，必须另行明确范围，本规范不得自动翻译。

## 一、核心原则

1. **以语义和可靠结构证据为准，不机械沿用错误的 Markdown 标记。**
2. **不总结、不压缩、不重写正文，不凭常识补写缺失内容。**
3. **作者原注、书名/副标题、署名、版本、版权页、题词、引文及有意义目录应按原书信息保护。**
4. **图片默认完整保留**；只有用户明确选择删图策略时才按第五节删除引用、审计损失；图片路径不能在格式化过程中被暗改。
5. **默认保持源语言和文字体系**。繁体不默认转简体；英文、日文、韩文及混排不作中文化；文字体系转换须明确授权并限于指定段落/语言范围。
6. **不确定是否为错误或第三方广告时，优先保留、标记复核。**
7. **以差量和可追踪证据修复**：原片段、修订片段、修订原因、是否影响可见信息可检查；无来源证据不做 OCR 字词事实校正。
8. **重复执行应幂等**：第二次运行不得因同一规则产生新标题、重复分隔符、继续丢图或累计改动。

### 语言识别与按需规则（R2）

- 优先采用电子书可靠元信息与段落上下文判定语言；自动检测仅作提示，混排时应按**段落/文本片段**而非整本书强制统一。标签采用 BCP 47，例如 `zh-Hans`、`zh-Hant`、`ja`、`ko`、`en`、`ar`、`he`；地区确实影响书写时才加 `-TW`、`-HK`、`-US` 等。判断不足时标记 `und`/待复核，不把“繁简字体”推断成唯一地区信息。
- **中文（简/繁）**：根据句读、原书段落和章节模式判断排版；不把异体、古籍字、专有名词或繁体原版强转；简繁授权转换时保护代码、链接、路径、公式、专名并保留可回查映射/样例复核。
- **英文等空格分词语言**：普通视觉折行通常合并为一个空格；遇到 `inter-` 换行 `national` 等连字符断词，只在能确认是行尾断词而非真实复合词时去连字符，否则列入复核；保留真实段落、诗行、对话、列表。
- **日文**：保留原有假名、汉字、全半角和日式标点；章次可出现 `第1章`、`第１章`、`第一章`、`第〇章` 等，不强插中文空格或简化汉字。纵排/竖排转写顺序不明时只提出复核候选。
- **韩文**：尊重词间空格、谚文音节与助词关系，不能按中文无空格拼接；章节模式、断行证据以韩文上下文为准。
- **中英混排及数字/符号**：保护 `C++`、`GPT-6`、单位、版本、公式、URL 与英文词界；不能机械在汉字与 ASCII 之间增删空格。其他语言均默认不强制套用中文标题和标点规则。
- **阿拉伯语、希伯来语等 RTL**：保持存储的逻辑字符顺序、数字与拉丁片段顺序；禁止按屏幕视觉顺序反转文字、标点或链接，不全局删除方向控制字符。复杂双向布局不能可靠确认时移交复核。

语言/书写体系分类是**修复策略选择依据**，不意味着必须为每种语言生成不同输出文件或强制在正文插入 `lang` 元数据；已有 front matter 中的语言标签可在有证据时修复，缺失时不必新增。

## 二、标题与层级修复

### 1. 按语义重新判断标题层级

不要机械沿用原文件中的 `#`、`##`、`###`、`####`。

对于书籍、电子书、PDF / OCR 转写文档，**默认优先采用下面这条主层级**：

```md
# 书名

## 第一章 章节名

### 章节内部的重要小节

#### 小节下面确实存在的进一步细分
```

推荐层级：

- `#`：整本书 / 整个文档的书名，只使用一次；
- `##`：主要章节、编号章节，尤其是“第一章 / 第二章 / 第 X 章”这一类正文主章节；
- `###`：章节内部的重要小节、方法、主题、案例组或独立论点；
- `####`：`###` 小节下面确实存在从属关系的进一步细分；
- `#####`、`######`：只有原文确实存在稳定的更深层结构时才使用，不要因为 OCR / 转换结果已经很深就机械保留。

#### 1.1 先识别“标题候选”，再决定 Markdown 层级

标题不一定已经带有 `#`。以下内容都应进入“标题候选”判断：

- 已经写成 `#`、`##`、`###`、`####` 等，但层级可能错误的行；
- `第一章……`、`第二章……`、`第 1 章……`、`Chapter 1……`、`第１章……` 等对应语言的章节编号行；识别后仍需正文上下文证据；
- `第一节……`、`第 1 节……` 等节级编号行；
- `第十七诀……`、`第一套……`、`第一招……`、`第一计……` 等在同一文件中稳定重复出现的编号主题；
- `一、……`、`（一）……`、`1. ……` 等可能承担结构作用的独立短行；
- 原本应是标题，但 OCR 后变成普通纯文字的独立短行；
- 原本用粗体、居中、特殊符号、较大字号表达，但转成 Markdown 后丢失标题语义的文字；
- 在同一章节内反复以相似长度、相似句式、相似位置出现，并且后面都跟随一段或多段正文的短语；
- 与前后段落之间有明显空行，并且自身不像完整正文句子的独立主题语句。

判断标题时要综合：

- **编号模式**：在当前语言中实际有效的章、节、篇、卷、Part、Chapter 等，不能把正文中的数字或列表项直接当章节；
- **上下文关系**：它后面的内容是否都在解释这个短语；
- **平行结构**：附近是否连续出现多个功能相同的短标题；
- **长度和标点**：标题通常较短，但不能仅凭“短”就判定；
- **正文完整性**：完整陈述句、长句、引用句、列表项通常不应被误判为标题；
- **跨页重复**：重复出现的页眉、栏目名、书名不等于正文标题。

不要只扫描已有 Markdown 标题；**必须同时检查可能丢失 `#` 的纯文字标题**。

#### 1.2 章节层级优先，不要让“栏目词 / 页面主题词”把整本书压深一层

电子书转换中经常出现这种错误结构：

```md
# 书名

## 某个栏目词 / 大主题词

### 第二章 怎样不战而屈人之兵

#### 向对方摆明利害关系
```

如果“某个栏目词 / 大主题词”只是栏目、页面主题、装饰性分组、重复标签，或者并没有构成稳定且必要的“篇 / 部 / 卷”结构，就**不要让它占用一级正文层级，导致所有真正章节和小节整体下沉**。

这类情况下应优先恢复为：

```md
# 书名

## 第二章 怎样不战而屈人之兵

### 向对方摆明利害关系
```

也就是说：

- `第 X 章` 默认优先判断为 `##`；
- 章内相互平行的主题标题默认优先判断为 `###`；
- 只有某个 `###` 下面确实还有稳定、重复、明确从属于它的子主题时，才使用 `####`；
- 不要因为文件前面出现一个短词、栏目名、宣传语、页面主题或视觉大字，就把后面几十个章节全部降为 `###`、把正常小节全部降为 `####`；
- `上篇 / 中篇 / 下篇`、`第一部`、`第一卷` 等只有在**确实覆盖多个章节、具有稳定多章分组意义**时，才可以作为额外结构层；如果只是装饰或页面标签，应避免占用目录层级；
- 如果保留某个非章节分组标题会造成正文主结构整体过深，应优先保证“书名 → 章 → 章内小节”的可读目录结构。

#### 1.3 根据同级重复关系校准层级

不要只看单个标题，要看一整段甚至整本书的重复结构。

例如，在同一章内连续出现：

```text
向对方摆明利害关系
抓住对方最在意的东西
不要急于暴露真实目的
给对方留下选择空间
```

如果这些短语后面各自都有正文，并且功能平行，那么它们通常应统一为同一级 `###`，而不是有的作为正文、有的作为 `####`、有的作为 `#####`。

如果多个“第 X 章”都处在同一层，而每章内部又存在一批相互平行的短标题，则应以这种**跨章节重复模式**反推正确层级。

必须注意：

- **书名和内部章节不能使用相同层级。**
- 避免明显的标题跳级，例如 `##` 后直接出现 `####`。
- 如果原文件标题符号数量明显错误，应根据内容关系重新调整。
- 不要因为某一页视觉字号较大，就自动判断为更高层级，必须结合上下文语义。
- 不要为了追求层级多而制造 `#####`、`######`；能用 3 层清楚表达，就不要机械保留 5 层。
- 修改一个标题时，要检查它前后的同级标题，避免只修一处造成全书层级不一致。

### 2. 合并被错误拆开的页面标题

转换文件中经常出现：

```md
## 走近博弈论

### 博弈的构成要素
```

如果判断两者实际上共同表达当前页面的完整主题，而第二行并不是正文中的独立子章节，应合并为：

```md
## 走近博弈论：博弈的构成要素
```

判断原则：

- 第一行通常是章节编号 / 章节名；
- 第二行通常是当前页面主题；
- 两者组合后语义更完整；
- 第二行下面没有多个同级子主题需要继续展开。

**不要机械合并所有连续的 `## + ###`**，不得凭空添冒号或改写标题词；若两行均是作者有意设置的标题，保留层级；证据不足时列为复核候选。

如果 `###` 确实是章节内部独立小节，则应保留原有从属关系。

### 3. 处理跨页重复章节标题

同一章节在多页重复出现同样的章名时，先判断是**重复页眉**、有意的正文标题，还是转换时的章节重复。只有确认属于非正文页眉，才删除重复项；真正的章节标题应只在章节开始处保留一次，**不能为每页凭空制造新的 `##` 章节**。

例如原稿反复出现 `## 重复博弈`，但“天长地久的聪明策略”与“为什么不带剑的契约必然无效”确为同章两个小节，可整理为：

```md
## 重复博弈

### 天长地久的聪明策略

（原小节正文）

### 为什么不带剑的契约必然无效

（原小节正文）
```

若这些句子并非原有小节，则**不得因示例而新增小节**；仍供 Workflow 定位的页面标记不可因合并而消失。

### 3.1 同级纯数字章节编号分隔符（继承上轮已明确要求）

对于已被上下文确认是**同级章节标题**的纯数字编号，优先统一为 `编号 + 一个普通空格 + 原标题`。只调整标题中的编号分隔，**原编号、前导零、标题内容、标题层级及顺序全部保留**：

```md
修复前：## 002滴水滚珠局
修复后：## 002 滴水滚珠局

修复前：## 003、引子
修复后：## 003 引子
```

此规则**不用于**列表项 `1. 内容`、版本号 `v1.2`、年份 `2026`、真实的章节体系 `第一章` / `Chapter 2` / `第１章`，也不默认移除英文或其他语言的合法编号标点（如 `1. Introduction`）。同级标题没有足够证据时只提示候选；不得为“连续编号”而补号、重排或改号。重复运行不应新增第二个空格。

## 三、正文与排版修复

### 4. 修复错误换行

OCR / PDF / PPT 转换后，常出现一句话被错误拆成多行。

需要根据语义判断：

- 本来属于一句话的内容 → 合并为正常句子；
- 本来属于一个段落的内容 → 恢复为正常段落；
- 本来属于列表、步骤、关系结构的内容 → 整理成 Markdown 列表；
- 不要机械把所有短行合并。
- 先隔离标题、诗歌、对话、引文、列表、表格、代码/公式、脚注、段落硬换行，避免普通段落合并伤及结构。
- 跨页合并须先确认同一段落连续且阅读顺序正确；Workflow 中不得为合并跨页句子而删除或移动必需的 `<!-- page:N -->`，无法兼容时保持原标记并列入复核。
- 语言差异按第一节执行：英文优先以空格连词、CJK 依词句语义断行，韩文保护词间空格，RTL 不按视觉行顺序倒序拼接。

重点保证：

- 阅读自然；
- 原意不变；
- Markdown 渲染正常。

### 5. 修复列表与缩进

检查并修复：

- 无序列表 `-`；
- 有序列表 `1.`；
- 多级列表；
- 列表缩进；
- 列表与正文之间的空行；
- OCR 导致的层级错乱；
- 孤立的缩进行；
- 本应从属于上一条内容却被拆平的项目。

应根据语义恢复合理层级，而不是只按空格数量处理。保护原有编号起始值、任务列表勾选状态、段落内换行与嵌套引用；不要将编号章节机械变为有序列表，反之亦然。

### 6. 修复 Markdown 表格

检查所有表格是否存在：

- 列数不一致；
- 表头错位；
- 分隔线错误；
- 单元格内容被拆到表格外；
- 多余或缺失的 `|`；
- OCR 导致的错误换行；
- 无法正常渲染的结构。

可以在**不改变原始信息含义**的前提下修复表格。

如果内容明显原本就是表格，但转换后结构损坏，可以根据上下文恢复为合理 Markdown 表格。

不要为了美观而重写表格内容。含多行单元格、合并单元格、公式或跨页续表时，标准 GFM 表格未必能无损表达；无法验证单元格对应关系时保留可靠结构或原稿片段并列入复核，不能猜补空格或拆散表格。

### 7. 清理 OCR / AI 转换异常

可以修复或删除：

- 经上下文或可靠原图比对证实的 OCR 乱码；
- 经确认非正文的孤立无意义字符；
- OCR 错误符号；
- 明显错误的断词；
- 多余空格；
- 能定位到转换重复而非作者修辞/引文的重复文字；
- 经证明为转换噪声的无意义数字或字母；
- 转换工具自动插入的辅助说明；
- 明显不是原书正文的 AI 转写提示。

但不要根据自己的知识擅自“纠正”作者观点、外文名称、数字或大幅修改原句。低置信 OCR、重影文本、错位脚注、跨页重复需要来源截图/邻近文字/同章重复模式佐证；无证据只能标记 `needs_review`。

### 7.1 结构保护与阅读顺序（R2）

- **保护区先于文本替换**：YAML front matter、围栏/缩进代码块、行内代码、数学公式、HTML 片段、表格、链接地址、图片地址、引用标识、脚注/尾注及其定义、原有显式锚点，默认不执行正文级正则替换；涉及保护区必须有针对性解析与验证。
- **保护引用闭环**：`[链接](url)`、`[文字][ref]`、`[ref]: url`、`[^注]`、`[^注]: ...`、`<a id="...">`、外部/内部锚点、图片 alt、表格内的合法链接必须保持有效；重命名标题时检查依赖其自动生成锚点的链接，不能假设不同渲染器的锚点算法一致。
- **作者内容与转换杂质区分**：版权页、作者序、前言、后记、译者注、图题、正式引用、可辨识原书目录和书中对广告的引用，默认属于原书信息；不得因为含公众号/二维码/账号或位置像页脚就当作无关广告。
- **Unicode**：保留组合字符、变体选择符、零宽连接符、数学符号、上标和有意义空格，不做全局 NFKC、全角转半角、标点或方向符清洗；遇到疑似损坏字形要标记来源证据。
- **阅读顺序**：双栏、图文环绕、跨页段落、注释、引用与图注先确认原有阅读顺序，再移动 Markdown 块；无法判定则保留现状并复核。

### 7.2 内容守恒与差量审计（R2）

修复前后按段落/区块做可比对 diff，至少核对：**可见文本与标题编号序列、图片引用（按策略）、链接目标与引用定义、脚注目标、公式/代码文本、原书元信息、页面标记（按模式）及阅读顺序**。记录删除的原文字面片段、位置、理由与证据；不能仅凭前后字符数接近判定保真。字符数、引用数量、文件哈希可作为辅助指标，但不能替代语义和区块比对。第二次使用相同策略运行应产生**零非预期差异**。

## 四、页面杂质清理

### 8. 删除顶部目录

如果文档开头包含从原书、PDF、PPT 等提取出的**冗余文字目录**，在用户未要求保留、且正文确实完整覆盖、无锚点/页码/来源信息损失时可以删除；原书正式目录或有索引价值的目录默认保留。

但必须注意：

- 保留书名；
- 保留副标题（如果它属于正式书名信息）；
- 不要误删真正正文；
- 只有在目录内容已由后文正文完整覆盖且不损害导航、页码定位与原书信息时才删除；不能把序言、译者说明、索引误当目录。

### 9. 删除页眉、页脚、页码和转换标记

删除明显不属于正文的内容，例如：

- 页眉；
- 页脚；
- 独立页码；
- 每页重复出现的书名；
- 每页重复的宣传文字；
- **独立交付**：已确认无定位、锚点、校对用途的 `<!-- page:N -->` 等转换标记可删除；仍有用途时保留；
- **Workflow**：用于页面单元、定位或验收的 `<!-- page:N -->` 必须原位保留；图片和页面顺序按实际合同保护；
- **批量修复**：逐文件检查是否依赖页码/页面顺序；依赖则保留，明确为无用残留时才删除，不能套用一刀切规则；
- `<!-- Image (...) -->` 等转换注释仅在确认未承载唯一资源/定位信息时可删除；
- PDF / PPT 转换工具生成的辅助说明。

但不要误删：

- 正文中的年份；
- 正常编号；
- 章节编号；
- 公式数字；
- 表格数据。

---


### 9.1 删除明显广告、联系方式和资源引流信息

如果可以确证原始电子书或转换稿中混入**非作者正文、第三方推广**，才删除相应广告片段，例如：

- `加微信：Sm99%10`；
- `添加客服微信：xxxx`；
- `朋友圈每日更新，获取请添加微信……`；
- `感谢您的阅读，如需要更多精品优质电子版书籍……`；
- 与正文无关的公众号、微信号、VX / V信、资源群、电子版获取方式等。

执行边界：

- 只有能够高置信判断为广告、联系方式或资源引流时才删除；
- 正文正常讨论“微信”“朋友圈”“公众号”等概念时必须保留；
- 如果广告被错误拼接在正文句尾，只删除广告片段，保留前面的正常正文；
- 不得因为清理广告而删除整段有价值正文。

- 广告可能被错误包装成 `#` / `##` / `###` 等标题、列表项、引用块或粗体短句；识别时应先去掉 Markdown 外壳再判断；
- **广告清理的默认单位是“广告片段”，不是“整行”。** 一行中只要仍包含正常正文，就必须保留正文，只删除广告前缀、广告尾巴、括号联系方式或嵌入式引流片段；
- 广告可能直接粘在正文前后，例如“更多资料加威信xxxx，正文……”或“正文……添加作者微信xxxx获取资料”；必须只剥离广告串，不能删除整句正文；
- **不能因为正文出现“微信、朋友圈、公众号、扫码、微信群、微信号、电子书、资源”等词就删除。** 正文讨论微信获客、朋友圈运营、扫码案例、公众号营销、联系人微信等，都属于正文；
- 高置信广告通常具有“书外引流目的 + 行动指令 + 联系方式/资源领取”等相互印证的线索，例如“添加客服微信领取盗版资源”；单独出现联系方式、二维码、作者联系方式或书中的推广案例**不足以认定第三方广告**。若来源归属不明，标记复核，不删除；
- 广告若被错误识别成标题，应删除该广告标题，并只修复由这个伪标题直接造成的子标题下沉；不得借广告清理之名批量重排与广告无关的标题；
- 删除广告后若留下残缺括号、孤立标点、空标题或标题跳级，应同步修复；
- 批量处理目录时必须递归检查目标目录下全部 `.md` 正文文件，而不是只扫描根层；完成后必须再次扫描高置信广告残留和标题跳级，并保留审计报告。

## 五、图片处理

### 10. 图片引用策略：默认保留、显式授权可删（R2）

允许以下三种选择；**未指定时必须用 `keep_all`**，不得从“只要文字”自行推断“删图”：

| 策略 | 触发条件 | 实际动作与必需校验 |
| --- | --- | --- |
| `keep_all`（默认） | 用户未明确提出删图 | 保留全部图片引用的出现次数、路径和相对顺序；不改名、不替换、不隐式迁移资源 |
| `remove_all` | 用户明确要求删除全部图片引用 | 移除范围内图片引用，保留独立存在的图题、正文及有用 alt 文本；记录删除数量、原路径、类型、位置和信息缺口 |
| `remove_page_images` | 用户明确只删除整页扫描图/截图 | 仅对确证为页面截图的引用执行删除；图表、插图、照片等保留，分类不确定时复核 |

引用形式不限于 `![说明](assets/page-001.png)`：还可能是 `![][id]` 加定义、HTML `<img>`、表格内图片、转义或带标题的图片写法。检查需按 Markdown 语义识别，不能仅用单一正则统计 `![](...)`；**不删除指向图片的普通文本链接**，除非用户另有明确指示。移除引用后，仅在可证明不被其他链接/图片引用时才清理孤立图片定义；不得顺手删图注和普通段落。如果图片语法中的 alt 是唯一已有的可搜索说明，可在保留原文、记录迁移位置且不误判为正文的前提下转为独立图注；不可靠时标记复核，不能编造图注。

#### 图片分类与信息损失边界

- **整页截图**：原始页面图，常与该页 OCR 正文重复；只有确认可搜索文字覆盖其可辨信息，才能标记“文本已覆盖”。不能仅凭文件名 `page-*` 推断。
- **真正插图/图表/公式截图**：有独立视觉意义；即使已有部分 OCR 文本，也不能因此认定图中的关系、标注、坐标轴已完整转写。
- **图片为唯一信息来源**：如仅有图片、无可搜索正文，`remove_all` 可以按明确指示删除*引用*，但必须记录 **`information_loss=true` / `needs_review`**，不得宣称原书信息完整；若任务同时要求完全保真，则属于冲突操作，应先停止该部分并报告不兼容性。
- **图片有 OCR 文本**：核对是否存在缺字、错序、图注、单位和结构性信息，无法确认则标记 `coverage=unverified`；不能根据图片凭空编造替代文字。
- **资源文件**：本规范只修改明确指定的 `.md` 引用；除非另获授权，不删除磁盘或仓库中的图片文件，也不改变真实路径。
- **Workflow 合同冲突**：若其定位/回归测试要求保留图片实体或引用，用户删图要求与之不兼容时不能静默覆盖合同，需报告阻塞项；能安全删图时仍须保持剩余页面与内容顺序。

#### 图片审计（按策略，而非统一守恒）

- `keep_all`：比较引用的**完整出现序列**（包含重复、路径、顺序及对应的 alt/定义关系），非预期变化数量应为 0。
- `remove_all`：输出原始引用总数、实际删除数、残余数（预期 0）、删除来源位置及不能文本化的信息；如正文中的合法语法无法识别，不能声称完成。
- `remove_page_images`：分别报告已删除页面图、已保留正文插图与无法分类的图片；对未删除部分核对路径、引用次数及顺序；对被删页面图独有的信息同样标记 `information_loss`，不得默认视为 OCR 完全覆盖。
- 三种策略均检查链接可用性与无意删除正文；**只列出变更的路径与例外**，单本不强制写出冗长 sidecar。

### 11. 区分“整页原始截图”和“正文插图”

#### 整页原始截图（仅在 `keep_all` 且可安全调整时）

若某张图片确是当前页面完整截图、文字已从其可靠转写，且在当前模式不破坏页面定位与阅读顺序，则优先排列为：

```text
标题 → 可搜索正文 → 原始页面图片
```

这只是**同一页面内的可读性优先方案**，不是跨页统一挪动所有截图的命令；若当前 Workflow 的页面锚点或图片顺序合同不允许调整，必须服从其合同。

#### 普通正文插图

图表、流程图、示意图、照片、案例图、插画及图注应保持与相邻正文的原有关系，不得因“页面图后置”规则而移至页尾。`remove_all` 下删除其图片引用时，须如实报告剩余文本不足以表达的视觉信息；`remove_page_images` 下不删除它们。

## 六、低频 / 特殊情况

以下规则只有检测到对应问题时才执行，不要为了套规则破坏正常文件。

### 1. 复杂图表或关系图页面

如果一页主要是：

- 流程图；
- 思维导图；
- 关系图；
- 复杂图表；
- 大量箭头与空间布局；

而 OCR 后的文字顺序明显混乱：

1. 尽量把可确定的文字关系整理成结构化 Markdown；
2. 默认保留原始页面图片；若明确采用删图策略，则依第五节记录可能无法文本化的信息损失；
3. 不要为了强制线性化而虚构关系；
4. 无法确定结构时，宁可少改，也不要凭空补充。

### 2. 无法确定是否属于正文的异常内容

如果某段文字看起来可能是：

- 页眉；
- 页面装饰；
- 图中标签；
- 正文；
- OCR 误识别；

且无法可靠判断，则优先保留，避免误删。

## 七、输出文件要求

### 独立交付的单本电子书

使用可可靠确认的真实书名作为 `<书名>.md`，不加「整理修正版」或「最终版」等后缀。书名不可靠时不要编造；提出复核或使用用户明确指定的名称。**此命名只用于实际电子书交付，不要求本规范文件改成书名。**

### Workflow 原位修复的路径边界

Workflow 原位修复不套用单本另存或其他项目的重命名约定：依已核验的工作流合同保留原路径、资源路径与文件身份；未经授权不改目录结构。

### 批量修复的范围与命名边界

- 批量模式只处理**明确指定的文件清单或根目录范围**；需要递归时只在该范围内递归枚举 `.md` 文件，遵守明确的排除项。不得推断默认目录名或自行扩展范围。
- **默认原位保留文件名、目录结构、相对图片/链接路径和书籍身份**。单本交付的 `<书名>.md` 命名建议不自动套用于批量现有文件。
- 只有用户明确要求统一命名并核实主文档、引用关系和重名风险后，才允许按该任务的命名合同迁移；批量修复本身不授权将主文件强制改为 `index.md` 或覆盖其他文件。
- 如果一个目录有多个 Markdown，不能凭文件名猜测主文档或合并/覆盖不同书籍；无法确认时加入 `needs_review`。
- 批量结果按本次指定的路径和报告约定交付；是否创建独立审计文件取决于任务需要，不为单本修复强制生成。

## 八、完成前的最终校验

修复前后必须按**当前模式和所选策略**核对，不能把不适用的默认项当缺陷：

1. 文档确为一本书且书名可识别时，是否恰好一个 H1 且它是书名；不要把 front matter 或围栏代码中的 `#` 计数；不明书名应复核。
2. 书名、章、小节的真实层级是否合理，是否有被栏目词无意义压深或标题跳级；不机械制造章节。
3. 未标记的标题与“标题+第一句正文”粘连是否由语义证据支持，是否把普通短句错升标题。
4. 同级纯数字编号标题是否只校正分隔符，并保持原数字（含前导零）、标题和层级；第二次执行不得继续改变。
5. 同一章的跨页重复标题是否是页眉，而非作者真实标题；是否保留必要页面标记。
6. 各语言是否**默认保持原文字体系**；只有授权时才执行指定简繁转换，且未触及英语、日语、韩语、专有名词或代码地址。
7. 中英文/日文/韩文/RTL 的断行、词界、标点及阅读顺序是否没有被机械转换破坏；连字符断词、RTL 方向不明时标记复核。
8. 原书元信息、目录/前言、引文、作者注、脚注/尾注、锚点、链接、引用定义、强调、代码、公式、HTML 和 Unicode 是否保持完整。
9. 错误换行、列表起始值与嵌套关系、表格单元格与顺序是否在有依据的范围内修复。
10. 页眉、页脚、广告、转换标记是否仅在证实非正文且当前模式允许时删除，不能误删正常文本。
11. `keep_all` 时图片完整序列与路径是否守恒；`remove_all` 时图片引用是否按请求清零且记录信息损失；`remove_page_images` 时是否区分两类图片并审计未决项。
12. Workflow 的 `<!-- page:N -->`、页面顺序、图片/资源合同和输出路径是否保留；批量模式的扫描范围、原命名和路径保护是否仅在明确指定场景启用。
13. 可见正文、章节编号、重要数字/专名、链接和脚注在差量比对中是否守恒；每处删除都有原因和来源证据。
14. 确定缺陷与复核候选是否分开统计；低置信 OCR、复杂图表、无可靠结构证据应进入 `needs_review` 而非强修。
15. 同输入、同参数二次执行，输出是否无非预期差异；未做真实二次执行时**不得声称幂等性已验证**。

如果尚有高风险内容缺失、损坏链接、策略冲突或未核验的来源问题，必须说明限制，不以“格式检查通过”替代“信息完整验收通过”。

## 九、完成后的回复内容

**实际修复电子书时**给出简洁可追溯的结果（修订规范本身时不应伪造这些统计）：

- 本次模式、来源语言/文字体系、是否授权转换、图片策略与页面定位策略；
- 标题层级修复、新识别标题、页面标题合并、同级数字分隔符修复的实际数量；
- 表格、断行、列表、OCR、目录、页眉/页脚、广告和转换标记的实际改动与证据；
- 图片引用变更前后数量、删除类型/原因、未覆盖的信息与待复核项（按第五节策略）；
- 链接、脚注、编号、元信息及重要正文在差量检查中的情况；
- 统计口径一致的可见正文字符数（建议排除 Markdown 格式符号、图片引用、HTML 注释和空白，不把字符数量当内容守恒证明）；
- 确定缺陷与候选各多少、真实执行过的测试与未执行项、是否做过二次运行，以及最终文件名。

单本修复最终直接提供 `.md` 下载文件；若无无法消除的 P0 冲突或信息缺口，不强制额外生成 JSON、报告或语言配置。对含未解决保真风险的任务，应明确标记“需复核”，不能声称完全修复。

## 最重要的执行原则

> **一条规则只定义一次，特殊情况只补充例外，不重复定义通用规则。**

> **优先根据文档语义进行整理，而不是机械根据原 Markdown 标记修改。**

> **不改变正文含义；图片默认保留、显式授权才按策略删除并记录信息损失；不因为修复一种文件的问题而给其他正常文件制造新问题。**

## 十、批量修复与验收

本节仅用于用户明确指定范围的批量修复；单本修复时跳过。

当任务要求处理指定文件清单或目录中的全部 Markdown 时，**不能以“脚本运行过”“文件最近被修改过”“Git 历史存在 format/cleanup/finalize 提交”“旧进度报告标记已完成”作为完成依据**。这些信息只能作为弱辅助证据，最终必须以当前文件内容为准。

### 1. 每轮都要重新扫描指定范围的当前内容

- 按任务明确给定的文件清单或根目录递归枚举 `.md`，遵守排除规则，不得扩展到未经指定的范围，也不得只读取旧的待处理名单或旧进度 JSON；
- 新增、改名、移动过的文件必须重新进入检查；
- 文件修改时间、最后提交时间、提交信息只用于帮助定位可疑文件，**不能直接判定“已格式化”**；
- 若 Git 历史显示“已格式化”，但当前内容仍违反本提示词，则以当前内容为准，重新修复。

### 2. “完成”必须同时通过内容级验收

至少检查以下项目：

1. 全文只有一个一级标题 `#`，且为书名/文档主标题；
2. 长文若只有书名而缺少结构，先检查原书是否确有章节；存在可证实章节而转换遗漏时才恢复，原书本就无章或证据不足时只列复核候选；
3. 顶部文字目录只有在确属冗余、正文已完整覆盖、当前任务允许删除且不损害导航和原书信息时才清理；需要保留的目录与目录图片按第五节策略处理；
4. 不得把目录项本身误当正文标题；正文标题应在正文实际出现位置恢复；
5. 检查疑似“标题与第一句正文粘连”，例如 `小节标题正文第一句……`；仅在能够可靠确认边界时拆开，否则列复核候选；
6. 检查 `□` / `▢`、独立的“第X章/第X节/第X课”等是否为真实遗漏的章节标记；不能把引用、公式、任务列表中的相同字样一律当缺陷；
7. 检查标题层级跳级、异常巨大标题、把整段正文误升为标题、OCR 乱码标题；
8. 检查页码、页眉页脚、转换器标记、`视觉补充` 等是否为非正文；`<!-- page:N -->` 仅在**当前批量任务逐文件确认可清理**时视作残留，定位所需时必须保留；
9. 检查超长 OCR 行及未分段的疑似整页文本；只有与原书段落证据相符时才修改，否则仅标记候选；
10. Markdown 图片引用按第五节选定策略验收：默认逐条守恒；显式删图时按范围、类型、路径、出现次数与信息缺口审计，不能以默认守恒判失败；
11. URL、链接引用定义、脚注、代码块、公式、表格、引用块、Unicode 等特殊结构必须继续满足第三节保护规则；
12. 对无法高置信自动修复的文件，必须列入 `needs_review`，不能为了让报告显示 0 问题而强行修改或忽略。

### 3. 必须识别“假通过”

以下迹象意味着**如果没有进一步内容级核验就宣告完成，属于假通过**。其中标题密度、OCR 长行、残余目录片段不能脱离来源证据独自判定缺陷：

- 文件有近期修改记录，但正文仍是原始 OCR 连续文本；
- 文件只有 `# 书名`，长篇正文没有章节/小节，且当前未核查原书是否实际存在结构；
- 文件已有很多后半部分标题，但前半部分仍存在大量标题与正文粘连；
- 旧脚本因缺少某种页面标记而跳过正文格式化；
- 顶部目录被部分删除，却未确认剩余文本是应删冗余还是有用原书目录；
- 自动校验只检查 Markdown 语法，却没有检查语义标题覆盖率；
- 历史提交名包含 `format` / `cleanup` / `finalize`，但当前内容仍不合格。

### 4. 推荐的批量验收输出

批处理结束后应生成或更新一份内容级审计报告，至少包含：

- 扫描的 Markdown 总数；
- 实际修改文件数；
- 通过文件数；
- 高风险 / 中风险待人工或深度语义检查文件数；
- 目录残留、显式章节标记残留、标题粘连、标题密度异常、超长 OCR 行等问题计数；
- 图片引用按本次策略统计的原数、删除数、保留数、路径差异及信息损失；
- 每个仍未通过文件的具体路径、问题类型和证据；
- 对“历史显示已处理但当前内容失败”的单独标记。

批处理的最终目标不是“脚本成功退出”，而是：

> **本次明确指定的批量范围内每个 Markdown 文件都经过内容级重新检查；能安全修复的已修复；不能安全自动修复的被明确列出，且不存在用修改日期、旧报告或提交信息掩盖的遗漏。**

### 5. “确定缺陷”与“复核候选”必须分开统计

批量处理时，**禁止把高召回启发式候选直接当成格式错误**。最终报告至少分为两层：

#### A. 确定缺陷（Actionable Defects）

只有**当前 Markdown 结构或来源证据能够直接证明违反了已生效的模式与策略**，才可列为确定缺陷。可能包括：

- 确认为单本文档且已有可靠书名时，正文 H1 计数不是 1（排除代码块、front matter）；
- 可靠证据表明某段标题与大段正文误并成一个标题，或真实章节出现位置丢失标记；
- 原稿明确的冗余文字目录、已确认的第三方推广片段仍残留；
- 当前模式允许删除、且已确认无定位用途的转换中间标记残留；**Workflow 必需的 `<!-- page:N -->` 不是缺陷**；
- 修改破坏了代码、公式、链接目标、脚注或可辨正文；
- `keep_all` 下图片引用发生非授权变化，或 `remove_all` 下仍有应移除的图片引用；
- 目标文件路径、页序或编号被违背当前模式的操作实际破坏。

**确定缺陷 ≠ 自动可安全修复**。即使证实有错，也只有能定位唯一修复位置、可保存原信息并通过差量验证时才自动修改；否则列为 `blocked/needs_review`，并保留明确缺陷计数，不能为了清零硬改。**超长行、标题密度低、独立数字、`□` 符号、联系方式或 `第X章` 字样本身不构成缺陷证据。**

#### B. 复核候选（Review Candidates）

以下指标只能说明“需要检查”，不能据此直接修改正文：

- 标题密度偏低、篇幅很长但缺章节、某行很长、疑似“标题 + 正文”粘连；
- `□` / `▢`、`1 / 2 / 3`、`第X章`、`Chapter 1` 等貌似结构符号，未确认是否为正文/列表/引用；
- 联系方式、微信/公众号、二维码、真实账号或 CTA **但作者归属/广告语境不清**；
- 句尾连字符、日文纵排残留、韩文断词、RTL 混排方向、复杂表格/图片的文本覆盖率不明；
- Git 历史有“已格式化”提交，但当前只检测到弱启发式候选。

例如 `记住：你如果想要从未得到过的东西，就要去做从未做过的事。` 可能是普通正文，不因“记住”就升成标题；`你加我微信，我就可以送你一个什么东西……` 可能是原书营销案例，不能只因出现“加微信”就删。

**报告分为两种状态**：`确定缺陷 0/N` 只表示已知、可客观判断的**结构项**未发现违规；`复核候选 M/N` 反映需要语义检查的风险。若有 `information_loss`、高风险 `needs_review`、来源缺失或不可验证合同，即使确定缺陷为零，也**不能标记“全文保真/发布验收完成”**。

### 6. 推广与广告残留必须按“可执行凭据 / 明确 CTA”判定

判定和删除的唯一通用标准见**第四节 9.1**，此处只补充通用批量修复的判定方式：

- 可以跨行识别被 OCR 分开的联系方式与 CTA，但仅在上下文证实为**非正文的第三方推广**时作为确定缺陷；单个账号、作者联系方式、引用中的“加微信”不能独立触发删除。
- 对确证广告片段做删除前后定位与审计；不顺便改变相邻正文的标点、空格、括号或标题。
- 专项扫描须分别报告**确认的广告残留数量**与**仅靠关键词/模式发现的复核候选**；不得为追求数字 0 而把候选强行删除或不报告。

### 7. 批量格式化的最终通过条件

对已明确指定的批量范围全量处理后，按如下终检：

1. **当前内容范围**：实际递归扫描全部指定 `.md`；新增/移动/改名文件均已纳入，不能只检查本轮修改的文件。
2. **结构与模式**：在适用情况下每本书有一个真实 H1；目录与章节由当前正文证据核验；页面标记、输出位置和文件名符合**已确认的当前模式合同**。
3. **确定缺陷**：确证结构/正文问题全部修复或如实列为未通过；没有将启发式候选伪装成错误。
4. **广告**：确认的第三方推广残留为零；未确认的联系方式/CTA 单独列入复核。
5. **图片**：按 `keep_all` / `remove_all` / `remove_page_images` 校验引用、路径、计数、顺序与信息损失；不再无条件要求“所有图片守恒”。
6. **信息保护**：元信息、语言、章节编号、引用/脚注、链接、公式、代码和重要正文已差量比对。
7. **幂等性**：如执行了真实二次运行，则报告差异/哈希结果；未执行不得写“通过”。
8. **可信依据**：修改日期、最近提交、历史报告和脚本成功退出只做辅助，不能证明当前文件合格。

推荐最终报告（仅在真实批处理后填写，不得虚构 `N`、`0` 或 `pass`）：

```text
模式/范围：batch / <已实际确认的文件清单或目录>
语言/图片/页面策略：<已实际使用值>
扫描文件：N；修改：N；结构客观通过：N/N
确定缺陷：N；复核候选：N；阻塞/信息损失：N
确认的第三方广告残留：N；可疑但未确认广告：N
图片：原 N / 删除 N / 保留 N / 无法识别 N
正文与引用差量：<通过/失败/未核验>
二次幂等检查：<通过/失败/未执行>
全文保真/发布验收：<通过/需复核/未验证>
证据：<文件路径、片段、变更记录>
```

历史存在 `format / cleanup / finalize / repair` 提交但当前内容未通过，标记 **“历史已处理，当前内容未通过（false pass）”**；不得依据时间戳跳过。

## 附录：R2 最小验证样例与维护边界

下列只是**规范预期**，不是已修复真实电子书的证据；实际应用时使用输入 Markdown、所选模式/策略、预期输出/复核状态构成可重复用例。

| 用例 | 给定片段或条件 | 预期行为 / 禁止的假通过 |
| --- | --- | --- |
| 简体同级编号 | `## 002滴水滚珠局` | `## 002 滴水滚珠局`，保留 `002` 与 H2 |
| 既有正确编号 | `## 002 滴水滚珠局` | 不再添加空格；二次执行零差异 |
| 繁体原版 | `臺灣的傳統文字`、`zh-Hant` | 默认原样保留；仅获明确授权才转换指定范围 |
| 英文断词 | `inter-` 接下一行 `national` | 没有可靠排版证据时复核，不能一律删除 `-` |
| 日文 | `第１章　はじめに` | 识别为标题候选；保留日文、全角数字/空格，不中文化 |
| 韩文 | `한국어 문장` / 词间空格 | 保留词界，不用中文无空格规则硬拼 |
| 中英混排 | `支持 GPT-6 与 C++` | 版本、连字符、加号、词界不被机械更改 |
| RTL | 阿拉伯语/希伯来语含拉丁和数字 | 保持 Unicode 逻辑顺序，复杂布局只给复核候选 |
| 默认图片 | `![图](a.png)` 重复两次 | 保留两次，核对路径和相对顺序 |
| 明确全删图 | `images=remove_all` 且图片有完整 OCR | 删除引用、保留可搜索正文并记录删除路径；OCR 覆盖不明时待复核 |
| 唯一图表信息 | `images=remove_all` 且图表没有可核对文本 | 记录 `information_loss=true`，不得声称全文保真 |
| 仅删页面图 | 页面截图 + 正文示意图 | 只移除已确认的页面截图，示意图保留 |
| Workflow | `<!-- page:2 -->` 用于定位 | 原位保留，不能作为残留失败；路径/顺序不擅改 |
| 独立交付 | 无依赖的 `<!-- page:2 -->` | 可删除；不删除可用元信息/锚点 |
| 批量修复 | 指定目录中存在多个 Markdown | 仅扫描授权范围，保留原路径与文件名；重命名必须单独授权，逐文件验收当前内容 |
| 引用/元信息保护 | `` `code` ``、`[^n]`、`[ref]: url`、front matter、公式 | 保持符号、定义与链接关系；无解析能力时避免自动替换 |
| 广告误判 | 书中人物说“加微信” | 默认保留为正文，不能关键词删除 |
| 低置信 OCR | 外文专名/页边残字 | 无来源证据只列 `needs_review`，不猜字 |

### 文档拆分条件（不默认生成 sidecar）

当前采用**单份核心规范 + 按需启用的语言/模式条件小节 + 内嵌最小用例**。只有后续确有独立维护者、不同语言规则高频变化或可执行流水线需要独立加载/版本控制，才考虑抽离 `ebook-md-language-<tag>.md`（语言附录）、`ebook-md-mode-<mode>.md`（模式覆盖）和 `ebook-md-tests.md`（测试集）；审计模板在批量自动化需要机器消费时才独立成文件。拆分后应按 **不可损害正文 → 模式必要合同 → 显式用户指示 → 核心默认 → 语言局部启发式** 的优先级加载与合并；附录只能增加差异规则，不得改写核心保真底线。
