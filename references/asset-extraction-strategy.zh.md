# 图片资产提取策略

这份策略回答“图片资产从哪里来、用什么方式提取、什么时候可以降本”。它属于
`document-to-markdown-assets` 的单页执行任务，不是新的 Workflow，也不是某个模型的
固定提示词。所有模型调用都必须受当前 source、授权范围和独立质量门约束。

## 本轮状态：`planned / not-run`

本轮只补齐 PPT/PPTX、PDF 和独立图片的资产提取方案及后期校准路线，不处理任何真实
source。高质量在线模型基准 → 本地视觉模型复现 → 质量比较 → 达标后降本，是后期可选
calibration route，默认关闭；本轮不调用在线模型、本地视觉模型、Apple Vision OCR、其他
OCR 或真实转换。没有本轮比较证据时，不得声称本地模型等价、质量达标或已经降本。

## 1. 先定义要保留的资产

同一页可能同时产生几类资产，不能只输出一张截图：

| 资产 | 用途 | 原则 |
|---|---|---|
| 原始输入图/嵌入图 | 保留来源像素和原始质量 | 不覆盖、不重新压缩；保留原 MIME 和 SHA-256 |
| 页面渲染图 | 回看页面整体版式 | PPT/PPTX 用自身 Office 渲染，PDF 用原始 PDF 渲染 |
| 复杂区域图/裁剪图 | 放大核对流程、表格、图表和关系密集区 | 只在整页图不足以复核时生成；保留父资产和坐标 |
| 结构化图像理解结果 | 提取图中文字、元素、层级、关系和可用于下游的提示词结构 | 必须保留模型、提示词版本、schema、原始响应摘要和差异 |

对复杂结构、关系密集或明确需要再次生成的资产，结构化理解结果必须进一步固化为
[`视觉重建信息包`](visual-reconstruction-profile.zh.md)：同时保存结构版（画布、区域、元素、
层级、关系、文字和样式）与提示词版（可复用 prompt、负向约束、版本和来源回指）。普通
泛化摘要不能替代 profile；无法确认的字段保留 `Unknown`/`needs-review`。

“提取出图片”与“理解图片内容”是两个动作：前者优先由确定性工具完成，后者才进入
视觉模型或 OCR。模型调用成功不等于资产正确。

## 2. 按来源格式选择方案

### 2.1 精美、正确的 PPT/PPTX

按以下顺序保留同一页的不同证据：

1. 从 PPTX 包内无损提取嵌入图片、媒体关系和对象 ID；
2. 用 PPT/PPTX 自身的 Office 渲染保存整页图，不能用旧 PDF 或固定截图代替；
3. 对图表、组合形状、矢量图和关系密集区，保存可复核的区域图或对象级证据；
4. 只有文字/结构无法表达图片语义时，才对整页或区域调用视觉模型；
5. 若同时存在明确属于同一材料的 PDF，比较两种画面；PDF 只作为视觉候选，不能静默
   覆盖 PPTX 的原生文字和对象关系。

### 2.2 PDF

1. 有嵌入图片时优先无损提取，并登记页面、对象或 XObject 来源；
2. 始终保留原始 PDF 页面渲染图，记录 DPI、尺寸和渲染器版本；
3. 对矢量图、扫描页、复杂表格和图文混排，按需生成高分辨率区域图；
4. 原生文本/布局不足时，使用视觉模型或 Apple Vision OCR 产生候选，不能把候选当成原文事实；
5. PDF 与 PPTX 画面差异较大时，以 PDF 页面图作为主视觉证据，同时保留 PPTX 差异证据。

### 2.3 独立图片（PNG/JPG/JPEG 等）

1. 原图直接登记为 `input-image`，不先转码、不改变尺寸；
2. 只有为了核对局部文字、表格或图形关系时才裁剪，裁剪图必须链接回原图；
3. 先判断图片是否具有可保留的语义内容；纯装饰图或无可复用语义的图片不能被模型“解释”成知识；
4. 需要结构化理解时，使用同一输入图、同一 schema 和同一质量评分表进行模型比较。

## 3. 先成功，再降本

成本路线不是“哪个模型先响应就用哪个”，而是先建立一次高质量基准，再验证低成本
路径能否复现同样的信息。

```text
同一页/同一资产
  → 高质量在线视觉模型（明确授权，仅作校准基准）
  → 固定 schema、提示词版本和评分表
  → 本地视觉模型复现
  → 对照完整性、文字、关系、裁剪、命名、追溯、耗时和成本
  → 修复提示词/schema/局部处理
  → 重复同一输入，直到质量门通过
  → 以后优先本地模型；不可用时才走便宜在线 fallback
```

### 高质量在线基准

- 只处理 smoke 页或代表性资产，不默认上传整份文档；
- 记录 provider/model、输入资产 SHA-256、schema/prompt 版本、请求范围、耗时、成本和
  结构化结果；不记录密钥、原始凭据或不必要的源文件副本；
- 基准结果是比较参照，不是当前 Markdown 已正确的证明。

### 本地视觉模型校准

- 必须使用与基准完全相同的输入、裁剪、schema、字段定义和评分维度；
- 比较模型实际提取的文字、图形元素、层级、父子关系、方向、颜色/线型语义、未知项和
  提示词结构，不只比较输出长度或 HTTP 状态；
- 发现差异时先修复提示词、schema、分块/裁剪和解析器，再重复同一输入；不得用后处理
  脚本静默填补模型遗漏；
- 本地模型只有在质量门、重复性和运行成本证据都满足时，才可登记为默认低成本路线。

### 便宜在线 fallback

- 仅在高质量基准已定义 rubric、且本地模型不可用或未达门时启用；
- 仍需使用同一 schema 和最小输入范围，并明确标记为 `budget-online-fallback`；
- fallback 通过网络可达、队列接收或返回 HTTP 200 不能直接升级为质量通过。

## 4. 统一质量比较表

每个候选至少按以下维度逐项评分，评分必须绑定当前 source/asset 和证据路径：

| 维度 | 要看什么 |
|---|---|
| 图片完整性 | 原图/嵌入图是否完整、是否被截断、重压缩或错配 |
| 文字可读性 | 标题、数字、表格单元格、标签和小字是否覆盖；错字是否可回溯 |
| 图形与关系保真 | 箭头、层级、分组、图例、颜色/线型和跨区关系是否保留 |
| 裁剪边界 | 裁剪是否包含必要上下文，是否遗漏边缘或引入其他区域 |
| 命名与来源 | `asset_id`、稳定文件名、显示名、occurrence、页码/区域和哈希是否一致 |
| 提示词结构 | 输出是否满足约定 schema，字段是否有证据，不得用空数组冒充“没有” |
| 可重复性 | 相同输入和版本是否得到可接受的稳定结果 |
| 延迟与成本 | 单页/单资产耗时、调用次数和实际成本；不能用估算代替记录 |

## 5. 选择和停止规则

- 没有高质量基准，不能声称本地模型“等价”或已经降本成功；
- 本地模型缺少关键文字、关系、来源定位或 schema 字段时，回到提示词/裁剪校准，不
  直接扩大到多页；
- 基准、本地和 fallback 均不可用时，保留原图与确定性提取，状态为 `needs-review`；
- 单页校准未形成明确 `passed`、`needs-review` 或 `failed` 终态前，不启动后续页面；
- 用户尚未补充的后续成本/能力方案保留为待确认扩展，不擅自新增第三条路线。

## 6. 必须留下的证据

至少在当前 package 的 `evidence/` 中留下：

- `asset-extraction-strategy.yaml`：源格式、资产清单、候选路线、选择理由和状态；
- `asset-quality-comparison.json`：同一输入下基准、本地和 fallback 的逐维度比较；
- `asset-quality-audit.json`：当前资产的完整性、视觉质量、来源追溯和停止/下一步；
- 需要修复时的提示词/schema 版本、差异摘要和再次运行结果。

只有独立 validator 重读资产、manifest、Markdown 和上述证据后，才能把结果用于后续
多页、多文件或生产成本结论。
