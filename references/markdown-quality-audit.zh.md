# Markdown 转换保真度审计指南

## 审计究竟要解决什么

PPTX、PDF、DOCX 或图片中的原始页面本来就是内容来源。转换成 Markdown 后，当前要确认的不是“读者会不会使用 Markdown”，也不是给 Markdown 追加新的阅读产品目标，而是确认：

```text
源文档中的内容和结构
→ 是否被准确地表达为 Markdown
→ 复杂图是否仍有可核对的页面/区域视觉资产
→ 每个结论是否能回到来源证据
```

转换可能出现文字遗漏、过度压缩、页面层级丢失、图形关系误读、版权混入正文、OCR 把不确定内容写成事实、图片或来源链接断裂，以及提示词/解析器没有覆盖的未知图形形式等问题。审计的业务目的，是发现这些转换错误，评分，登记修复任务，修改结果，再复核修改是否恢复了源文档的内容与结构。

审计不是月度制度，不是独立 Workflow，也不是新的业务目标。它是 `document-to-markdown-assets` 在转换过程中或已有结果上的质量校验与修复闭环：

```text
发现转换偏差 → 记录来源证据和风险 → 评分
→ 检查是否存在未知/未覆盖形式 → 最小修复 Markdown/资产登记
→ 修改后复核 → 通过或保留 needs-review
```

## 转换保真度的检查方向

以下是要排查的转换问题，不是对读者使用方式的评价。

### 1. 内容完整性与原意保留

- 标题、主题、模型名称、分类、编号和页内要点是否保留；
- 核心概念、步骤、层级、并列项、应用场景、限制条件、底部说明和结论是否齐全；
- 图中出现但正文没有的关键文字是否已补充，或明确标记为未确认；
- 表格、问题链、分支、多层对比和结论列是否被压扁成模糊概括；
- 改写、合并或排序是否改变原文含义；
- 原文缺失、OCR 候选和人工补充是否被错误地混成确定事实。

常见问题：右侧结论列省略、问题链只剩第一层、并列项被合并成“等”、底部限制条件消失。

### 2. 页面、章节和版面结构映射

- 页码、页面边界、章节顺序和标题归属是否正确；
- 原页面的分区、分组、表格、列表和层级是否在 Markdown 中有对应表达；
- 页面上的文本块、图形块和嵌入媒体是否仍能对应到来源位置；
- 多页内容是否被错误合并或拆开；
- 单页修改是否能局部完成，且不意外覆盖其他页的结果。

这里检查的是源页面结构是否被保留，不是评价 Markdown 的使用习惯。

### 3. 图形结构保真

- 流程方向是左到右还是上到下；
- 金字塔底层/顶层、漏斗入口/阶段/出口是否正确；
- 循环方向和闭环是否保留；
- 树状图父子节点和分支是否正确；
- 矩阵两个维度和区域位置是否清楚；
- 箭头、连线、分组和空间映射是否遗漏；
- 并列分类是否被误写成先后步骤；
- 时间阶段、运营区域和动作是否被错误绑定。

关系无法确认时，写“原图显示为……，关系待核对”，并保留对应视觉资产；不能根据文字顺序猜测空间关系。

### 4. 未知形式与覆盖完整性（独立闸门）

复杂图形不能只按提示词中预先列出的类型检查。每页都必须先做一次开放集合扫描，确认页面是否出现了未被当前解析器、Skill 或提示词明确命名的形式，例如：

- 组合图、嵌套容器、自由形状、徽标/图标语义、渐变或颜色编码；
- 多入口/多出口流程、跨区连线、回环、隐藏交叉线、跨页续接；
- 透视图、同心层、时间轴与区域叠加、非规则矩阵、双向比较；
- 图例、脚注、注释、编号、符号、颜色/线型所表达的约束；
- 任何“无法归入已知类型”但可能承载语义的文字块、图形块或空间关系。

未知形式检查不是让执行器猜测新事实，而是防止静默遗漏。对每个候选未知形式必须记录：`unknown_form_id`、来源页/区域、可见证据、当前解析覆盖、遗漏风险、下一步复核方式和状态。无法确认时保留整页或局部原图，并使用 `Unknown` / `needs-review`；不能因为提示词没有对应枚举就跳过。

未知形式闸门失败条件：

- 页面存在未登记的语义文字、连线、分组或图例；
- 复杂区域被标成“已完成”，但没有说明覆盖了哪些形式；
- 视觉复核提示词只返回预设关系，未声明开放集合扫描结果；
- 资产、manifest 或 Markdown 没有记录该未知形式的来源位置。

### 5. 来源、原文和不确定性边界

- 哪些内容来自来源原文，哪些是整理、结构说明或人工补充；
- OCR 结果是否只作为候选，而不是静默覆盖可信的原生文本；
- 疑似笔误是否标记“原图如此，待核对”；
- 无法判断的事实是否保留 `Unknown` / `needs-review`；
- 版权、转载、授权和来源广告语是否与转换正文分开；
- 人工补充是否有来源或明确标注，是否冒充原文。

### 6. 视觉资产、命名和来源追溯

- 原始页面、复杂局部图和嵌入图片是否存在且可打开；
- 来源文件、页码、节点/区域和资产路径能否相互追溯；
- Markdown 图片链接、manifest 和实际文件是否一致；
- 文件名是否稳定，不依赖随机前缀或原始文件名碰巧可用；
- 同一资产多次出现时，是否保留每次来源出现记录；
- 去重是否只去掉重复文件，而没有丢失来源出现事实。

### 7. 复核、修复和结果状态

- 每个问题是否有来源证据、风险、修复动作和验收条件；
- 修改是否只影响当前页/区域，并保留上一版有效结果；
- 修改后是否重新检查受影响内容和结构；
- `needs-review` 是否保留，而不是为了达到分数强行关闭；
- 测试、历史评分和 fixture 样例是否没有被冒充为当前业务结果。

### 8. Markdown 默认阅读顺序与形式选择

对于常见的图文混排页面，面向读者的 `index.md` 默认采用以下顺序：

```text
标题
→ 一句话主题/范围
→ 核心文字、列表、表格和分区
→ 图示关系说明（明确标记为整理说明，不冒充原文）
→ 应用场景、限制条件和来源/不确定性说明
→ 【需要保留的】原始页面图、复杂区域图、嵌入图片
→ 待核对/未知形式清单
```

需要进入读者层的原始页面图和复杂区域图不得放在标题或正文文字之前。这样读者先获得文字和结构，再使用原图核对复杂关系。`reader_image_policy` 为 `retain`/`needs-review` 的图片必须保留在 Markdown 中，并通过 manifest 追溯到来源页/区域；明确为 `text-only`、Markdown 可完整表达且没有语义视觉或未决关系的页面可设为 `omit`，此时工程页面图只留作证据，不写入 Markdown。二维码只记为忽略元素，不解码、不裁剪、不作为读者图片。

这个顺序是常见图文页面的阅读 profile，不是所有输入类型的固定模板。文字型页面可以直接使用段落、列表或表格；流程、树状、矩阵和时间线可以在关系明确时使用 Mermaid 或其他结构化表达；表格、图表、公式、代码、多栏、手写、低质量扫描和跨页结构应按其实际形态选择表达方式。整页图不足以支撑复核时才增加核心区域图；无法确认时保留图片和 `needs-review`，不能为了套用顺序而补写内容。

## 评分方法：每页 100 分，目标至少 95 分

评分衡量的是转换保真度。每个维度独立评分，不能用一个维度的高分抵消另一个关键维度的缺陷。

| 评分方向 | 权重 | 独立通过线 | 主要看什么 |
|---|---:|---:|---|
| 来源保护与证据可追溯 | 10 | 9 | 内容、结构和资产能回到来源页/节点/区域 |
| 页面与章节结构映射 | 14 | 12 | 页码、分区、层级、顺序和单页边界；包含固定阅读顺序 |
| 内容完整性与原意保留 | 23 | 20 | 主题、概念、步骤、分支、结论和限制条件 |
| 图形结构保真 | 23 | 20 | 方向、层级、箭头、循环、矩阵和并列关系 |
| 来源/版权/不确定性边界 | 10 | 9 | 原文、OCR 候选、人工补充、版权和 Unknown 分层 |
| 视觉资产与链接追溯 | 10 | 9 | 页面/区域资产、命名、manifest、链接和去重记录 |
| 未知形式与覆盖完整性 | 5 | 5 | 开放集合扫描、未知形式登记、覆盖声明和复核状态 |
| 修复复核、测试与局部恢复 | 5 | 4 | 问题可修、修改可复核、失败不被伪装为通过 |
| **总分** | **100** | **95** | **总分 ≥95，且每个维度达到独立通过线** |

内容完整性和图形结构保真不得低于各自满分的 85%。未知形式与覆盖完整性为独立硬门，必须满 5 分；不能用其他维度的高分抵消未覆盖结构。

### 95+ 目标画像

实际执行以“安全余量目标”作为修复终点：总分目标为 `97/100`，而不是刚好 95。建议目标分配为：来源保护 10、结构映射 13、内容完整 22、图形保真 22、来源边界 10、视觉资产 10、未知形式 5、修复复核 5。任何 P0 问题、独立通过线失败、未知形式未满 5 分或没有修改后复核，都不得进入 `accepted`。

修复优先级固定为：P0 关键遗漏/关系错误/来源混淆/断链/未知形式缺失；P1 细分内容、复杂区域映射和修改后复核；P2 术语、锚点、相邻页隔离和恢复说明。详细目标见 `references/quality-targets.zh.md`。

### 一票否决

出现以下任一情况，不得标记 `accepted`，即使总分看起来达到 95：

- 关键内容遗漏，导致源文档的重要信息无法对应；
- 复杂图的方向、层级、箭头或区域关系被错误表达；
- 版权、转载或授权文字混入转换正文；
- 不确定内容被写成确定事实；
- 工程字段或临时 OCR 内容进入正式 Markdown；
- 视觉资产缺失、断链或无法追溯到来源；
- 未执行未知形式扫描，或存在未登记的未知/未覆盖结构；
- 没有修改后复核，或把历史评分当作当前评分；
- 单页问题只能通过重做整本才能修复，说明局部恢复边界没有建立。

## 从评分到修复任务

不要只写“页面质量不高”。每个问题至少登记：问题、来源证据、风险、修复动作和验收条件。

```yaml
task_id: page-05-content-001
page_id: page-05
dimension: content_completeness
problem: 原图中的细分结论没有进入 Markdown
evidence: 原始页面右侧有七个结论项，Markdown 只有前三项
risk: 源文档的重要结论无法逐项对应
action: 补齐七个结论项，保留原图，并标记仍需核对的文字
acceptance: 七个结论项均有来源对应项，且没有引入来源外内容
status: open
```

未知形式问题使用同一任务格式，但必须额外填写覆盖字段：

```yaml
task_id: page-24-unknown-form-001
page_id: page-24
dimension: unknown_form_coverage
unknown_form_id: p24-region-02
problem: 三零/三管区域存在颜色分组和跨组连接，预设提示词没有声明扫描该形式
evidence: PPTX 形状、连接线和页面局部图均显示该区域
difference: 当前 Markdown 只写四组名称，未说明颜色分组和连接是否有语义
risk: 读者可能把并列组误读成单一路径，且颜色编码可能被静默丢失
action: 增加开放集合扫描结果；补充区域图；无法确认的连接标记 needs-review
acceptance: 该区域有覆盖结论、资产链接、来源 occurrence 和未决项；无未登记语义对象
status: needs_review
```

修复原则：先修复内容缺失和关系错误，再修复未知形式和资产断链；一次只改当前页或区域；不以无来源补写掩盖缺口；保留上一版有效结果；修改后复查受影响维度、一票否决项和未知形式闸门；仍无法确认的内容保持 `needs-review`，不要为了凑 95 分强行关闭。

### 修改后复核与局部恢复

每个 `resolved` 任务必须同时拥有修改前证据、修改后的文件哈希或版本标识、复核日期/运行 ID 和验收结论。复核至少覆盖：

1. 修改区域的文字、层级、关系、来源边界和资产链接；
2. 未被修改的相邻页/区域没有被覆盖或重排；
3. manifest 的 `source_occurrences`、资产 SHA-256 和 Markdown 链接仍一致；
4. 未知形式扫描结果仍存在，新增的 `needs-review` 没有被静默删除；
5. 失败时可以从上一版有效结果恢复单页/单区域，不要求重做整本。

如果没有这些证据，任务状态只能是 `open` 或 `needs_review`，不能写 `resolved`/`accepted`。
