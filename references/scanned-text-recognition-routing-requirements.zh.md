# 扫描文字页识别与 Markdown 结构路由需求

本文件是“文档转 Markdown”对无原生文字层 PDF、扫描页和图片页的专项需求基线。它先于
具体模型、提示词和适配器实现；任何实现不得把 Apple Vision OCR、mac96 30B 或更小模型
预设为固定主路线。路线只能由同一真实页面、同一质量量表和当前运行证据决定。

## 1. 本轮目标

在保留原始可见文字和逐页来源证据的前提下，把扫描文字页转换为可读、可搜索、结构可复核的
Markdown，并在质量、耗时和资源消耗之间建立可解释的按页路由。非空输出、文件存在、
Markdown 可打开、SSH/HTTP 可达或模型枚举成功都不是质量通过证据。

## 2. 三个不可合并的阶段

1. **文字识别 `text-recognition`**
   - 输入是一张当前页面渲染图或当前区域图。
   - 输出是原始可见文字候选、坐标、置信度、引擎/模型和调用参数。
   - 微信号、二维码附近说明、推广语、页眉页脚和其他异常文字都必须原样保留。
   - 不执行广告删除、摘要、改写或语言美化。
2. **Markdown 结构重建 `markdown-structure-reconstruction`**
   - 把有来源回指的文字候选或直接视觉转写组织成标题、正文自然段、列表、目录和其他
     可由 Markdown 表达的结构。
   - 只有当前页面能确认的标题、层级、列表和段落关系才可写入；不确定结构保留
     `Unknown` / `needs-review`。
   - 跨页连续性是独立校验，不得把相邻页文字静默写成本页事实。
3. **广告分类及处理 `advertising-classification-and-treatment`**
   - 消费前两阶段的只读输出，独立产生候选分类、标记或处理建议。
   - 本轮默认 `preserve-only`：不隐藏、不删除、不改写任何疑似广告文字。
   - 详细边界见 [`advertising-content-policy.zh.md`](advertising-content-policy.zh.md)。

## 3. 功能需求

| ID | 需求 | 通过证据 |
|---|---|---|
| SCAN-R001 | 纯文字扫描页不得只产出平铺 OCR 行；应重建可确认的标题层级、自然段、列表和目录结构 | 真实页逐项人工评分与结构守卫 |
| SCAN-R002 | 标题只能来自显式章节标记或当前页可复核的视觉层级，不得为了排版完整而臆造 | raw → Markdown 行级回指；无来源标题数为 0 |
| SCAN-R003 | 同一句因版宽换行时可合并；独立段落、列表项和目录项不得错误拼接 | 真实正文页、目录页和列表页对比 |
| SCAN-R004 | 提取阶段保留全部可见文字，包括微信号、推广语、二维码附近说明、页眉页脚和异常内容 | raw coverage 与异常内容保留检查 |
| SCAN-R005 | 广告分类与删除规则不得出现在基础 OCR/视觉提取提示词中 | 提示词静态检查与保留回归测试 |
| SCAN-R006 | 原始 OCR JSON、bbox、置信度、模型原始响应、页面图和原始 manifest 只读保存 | 哈希与证据路径检查 |
| SCAN-R007 | 页面渲染载体图与读者层语义图片区分；扫描载体图不自动成为 Markdown 图片 | reader image policy 与 manifest 类型检查 |
| SCAN-R008 | Apple Vision OCR、OCR+确定性结构重建、小视觉模型、30B 视觉模型在相同页面和量表下比较 | 固定 source/page/image SHA 的 benchmark record |
| SCAN-R009 | 比较至少覆盖标题、正文分段、目录、列表、页眉页脚、标点、跨页连续性和异常内容保留 | 八维评分表与失败类型清单 |
| SCAN-R010 | 每次测试记录 source SHA、页码、图片 SHA、路线、模型、参数、提示词版本、耗时、资源和输出路径 | benchmark contract 校验 |
| SCAN-R011 | 低置信度、结构失败、复杂布局和异常内容遗漏必须触发升级或人工复核，不得静默通过 | route decision 与 validator 结果 |
| SCAN-R012 | 小模型只有经过真实页面测试才能进入候选路由；模型说明、参数量和枚举结果只用于筛选 | 当前 source 的逐页结果 |
| SCAN-R013 | 下载、安装新模型或改变 mac96 服务/运行状态前，先核实官方来源、许可、磁盘、内存和适配，并取得相应授权 | inventory 与授权记录 |
| SCAN-R014 | validator 必须检查语义正文覆盖、结构、空页、异常页、图片策略和证据完整性 | 失败用例与独立 validator 输出 |
| SCAN-R015 | 任何路线都不能凭非空、文件存在、可打开或调用成功判 `passed` | 质量门和反例测试 |

## 4. 代表性测试集

测试集必须从当前真实 source 中冻结，至少包含：封面/标题页、普通正文页、目录页、显式列表页、
低置信度页、复杂布局页、跨页连续样本和异常内容样本。页码只是选择结果，不是永久硬编码。
`p001-p005`、`p013`、`p127` 可以优先核实，但只有页面特征和证据路径确认后才能进入冻结清单。

每个样本记录：

- `source_fingerprint`、`source_page`、`render_sha256`；
- 页面类型与选中理由；
- OCR/模型、版本、参数、提示词 SHA/版本；
- 端到端耗时、模型推理耗时、峰值内存/显存或 `Unknown`；
- raw 输出、结构化 Markdown、评分、失败类型和人工复核者。

## 5. 路由决策边界

- 不设静态的“文字页总是 OCR”“文字页总是小模型”或“复杂页总是 30B”。
- 路由先执行廉价的页面特征与已冻结证据检查，再选择当前已验证的最低成本候选。
- OCR 文字覆盖高但结构守卫失败时，可以进入确定性结构重建；结构仍失败再升级视觉模型。
- 小模型只有在对应页面类型达到质量门时才可替代 30B；没有同类页面证据时为 `unverified`。
- 30B 超时、空响应、不可解析或结构/文字质量失败时，不得循环消耗；保留失败并回退到其他已验证路线或人工复核。
- 任一路线漏掉可见异常文字、臆造标题/层级、错误合并自然段或丢失目录/列表时必须失败或升级。

最终阈值必须由真实基准报告冻结；在报告完成前，所有默认路线均为 `calibration-pending`。

## 6. 当前证据快照（2026-08-18）

- 已核实的 source fingerprint：
  `044b9dc9e5884496388fab3d6bc4eb8aee68698b7dd439130fb81658d54b0295`，历史报告记录 135 页。
- 原 PDF、135 页 Apple Vision OCR 包和读者版目录当前不在用户给出的原路径，不能假装仍可复读。
- 仓库忽略目录保留了同一 source 的 `p001-p005` 页面渲染图；`p001` 有完整 30B 输出，
  `p002` 有 30B partial/超时证据，其余页保留在线回退记录。它们可用于受限校准，不能代表全书。
- `p001` 视觉上存在微信号、二维码和“禁止外传”等异常/推广候选文字。当前只能确认这些可见
  内容必须保留；是否属于广告、如何标记或处理仍由独立后置策略决定，本轮不删除。
- `p013`、`p127` 和完整 Apple OCR 原始 JSON 尚未重新定位；相关比较必须标为 `blocked-evidence-missing`，
  不能从读者 Markdown 反推成原始 OCR 证据。

## 7. 本轮完成判定

只有以下条件同时成立，才可以把某一页面类型的路线写成“已验证”：

1. 同一真实页面至少有 Apple Vision OCR、30B 和一个实际可运行的小模型结果；若现场没有小模型，
   必须明确停在 `blocked-model-not-installed-or-not-authorized`。
2. raw 文字和结构化 Markdown 分层保存，广告后置策略未改变 raw 或读者正文。
3. 八个质量维度均有人工可复核评分与失败说明；关键可见文字无静默遗漏，臆造结构为 0。
4. 耗时和资源值来自实际运行或明确为 `Unknown`，没有用参数量替代测量。
5. 独立 validator 和相关测试通过，真实报告保留绝对证据路径和 source/page/image SHA。
