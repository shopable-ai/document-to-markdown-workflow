# 视觉重建信息包

图片资产除了“保留原图”，还可能需要保存一份能交给后续图像模型的重建信息。该信息包
专门服务于复杂结构图、流程图、矩阵、关系图、图文混排和有明确风格要求的图片；它不是
普通 OCR 摘要，也不是把模型的泛化描述当成事实。

契约见 [`contracts/visual-reconstruction-profile.yaml`](../contracts/visual-reconstruction-profile.yaml)。
默认写入当前资产包的 `evidence/visual-reconstruction-profile.yaml`，并在
`manifest.yaml` 的对应视觉资产上登记 `reconstruction_profile`。原始图片、页面图和裁剪图
仍是第一事实层，profile 不能覆盖或替代它们。

## 保存两种互补结果

同一个复杂资产建议同时保留：

1. **结构版**：画布比例、阅读方向、区域、节点/元素、层级、箭头/连线/邻接关系、文字位置、
   色彩/线型编码和未决项。它让后续模型或人工可以重新安排版面，而不是只得到一段摘要。
2. **提示词版**：根据结构版生成一份可复用的中文提示词，明确主题、构图、层级、视觉元素、
   必须出现的原文、风格、画布和禁用项。提示词必须记录版本，并能回指结构字段和来源区域。

如果证据不足，保留 `structure-only`、`prompt-only` 或 `insufficient-evidence`；不要用一份
“看起来完整”的泛化提示词掩盖未识别的关系、文字或风格。

## 最小提取清单

- **画布**：宽高、横竖屏/方形、比例、背景。
- **构图**：主阅读方向、布局类型、区域边界、视觉中心、层级和留白。
- **元素**：每个节点/对象的类型、可见内容、位置、大小、颜色/线型、所属区域。
- **关系**：来源与目标、关系类型、方向、连线/箭头/分组依据；不确认的关系写 `Unknown`。
- **文字保真**：可读文字逐字保留，标出语言、字号/字重/对齐等可见特征；模糊文字单独列出。
- **风格**：调色板、背景、线条、材质/纹理、光照/景深或插画/信息图风格。
- **生成约束**：必须保留项、不可新增项、负向约束和信息密度限制。
- **证据**：原图/页面图/区域裁剪、source span、提取路线、schema/prompt 版本和置信度。

## 给图像模型使用的边界

Workflow B 可以把 profile 作为参考资产的一部分，使用其中的结构和提示词重新组装请求；
它不能把 profile 当成复制原图版式的授权，也不能把生成成功或 HTTP 200 当成重建正确。
生成前后仍须经过独立的图片验收，尤其检查文字可读性、结构关系、事实边界和是否臆造了
来源没有的元素。

profile 的状态只表示重建输入的证据状态：

| 状态 | 含义 |
|---|---|
| `available` | 结构、提示词和来源证据可被下游读取 |
| `needs-review` | 已保存候选，但存在未裁决文字、关系或风格字段 |
| `mode=structure-only` | 结构足够，尚未形成可直接调用的完整提示词 |
| `mode=insufficient-evidence` | 仅保留原图和有限候选，不得声称可重建 |
| `not-applicable` | 纯装饰或无可复用视觉语义的资产 |

无论状态如何，都保留原始资产及其 SHA-256；不要为了得到一份“完整提示词”而删除
`Unknown`、候选或冲突证据。
