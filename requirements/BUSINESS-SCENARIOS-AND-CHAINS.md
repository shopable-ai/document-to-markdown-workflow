# 文档资产化业务场景与链路

> **Brownfield 参考：** 当前尚未通过 V1，本文件不能作为 C10—C11 的当前业务权威。当前中文业务入口见[项目需求说明](../项目需求/说明.md)。

这份文件不讲实现，而讲“人会遇到什么情境，系统应该怎样表现”。它帮助人检查：AI 推导出来的功能和行为，是否真的对应到了实际使用情境。

这里保留的是旧场景草稿；旧 `authoritative-draft` 状态已经被目录级降级覆盖。

## 先看 8 个主要场景

| 场景 ID | 场景名称 | 谁会进入这个场景 | 期待的终点 | 当前状态 |
|---|---|---|---|---|
| SCN-DOC-001 | 单一来源转换 | 读者、执行者 | 当前来源被整理成独立 Markdown 包 | draft |
| SCN-DOC-002 | 多格式候选确认 | 执行者、复核者 | 分清同一材料候选还是独立来源 | draft |
| SCN-DOC-003 | 复杂视觉内容处理 | 读者、复核者 | Markdown 与视觉证据同时成立 | draft |
| SCN-DOC-004 | 页面 Markdown 分阶段修复 | 执行者、复核者 | 先小范围证明，再扩大修复 | draft |
| SCN-DOC-005 | 长文档受控运行 | 执行者、验收者 | 长任务可观察、可停止、可恢复 | draft |

## 场景逐项说明

### SCN-DOC-001 单一来源转换

什么时候会发生：

- 用户给出一个明确来源，并说明输出范围或页码。

人希望发生什么：

- 结果只讲当前来源。
- 结果能独立阅读和搜索。
- 需要保留的复杂视觉内容能被人继续核对。

如果事情不顺：

- 来源不明、范围冲突或旧内容污染时，必须停回来源确认。
- 独立验收不过时，不得给出 `passed`。

主要对应：

- 需求：REQ-DOC-001..007、REQ-DOC-009..012、REQ-DOC-018、REQ-DOC-022
- 功能：FUN-DOC-001、FUN-DOC-002、FUN-DOC-005、FUN-DOC-006

### SCN-DOC-002 多格式候选确认

什么时候会发生：

- 同时出现多个可能相关的 PDF、PPTX 或其他来源。

人希望发生什么：

- 明确看到它们是“同一材料候选”还是“本就不同来源”。
- 差异和选择依据被保留下来。

如果事情不顺：

- 关系不明时保持分开，或标记 `needs-review`。
- 不能只按名字相似就自动配对。

主要对应：

- 需求：REQ-DOC-001、REQ-DOC-008、REQ-DOC-012
- 功能：FUN-DOC-004

### SCN-DOC-003 复杂视觉内容处理

什么时候会发生：

- 页面意义依赖位置、方向、层级、颜色、图例或图形组合。

人希望发生什么：

- 既有可搜索的 Markdown，又有可核对的图片证据。
- 问题、修复依据和未确认部分都能被看见。

如果事情不顺：

- 原图不能保留、裁切不够或证据不足时，只能保留 `structured-only`、`needs-review` 或失败状态。
- 不能因为“识别出了文字”就说视觉关系已搞清。

主要对应：

- 需求：REQ-DOC-003、REQ-DOC-005..007、REQ-DOC-010..014、REQ-DOC-021
- 功能：FUN-DOC-003、FUN-DOC-007、FUN-DOC-008、FUN-DOC-009

### SCN-DOC-004 页面 Markdown 分阶段修复

什么时候会发生：

- 已有页面单元需要做读者层修复。

人希望发生什么：

- 第 1 页先证明修法可行；
- 第 2–5 页再做小批量；
- 人工复核通过后才允许更大范围。

如果事情不顺：

- 任一阶段失败或需要复核时，不能继续扩大。
- 原始 OCR、页面图和其他原始证据不得被覆盖。

主要对应：

- 需求：REQ-DOC-004、REQ-DOC-012、REQ-DOC-016、REQ-DOC-017
- 功能：FUN-DOC-002、FUN-DOC-005、FUN-DOC-011

### SCN-DOC-005 长文档受控运行

什么时候会发生：

- 文档页数多、处理时间长，或需要跨阶段持续推进。

人希望发生什么：

- 当前页、当前阶段、当前状态、停止点和恢复点都可见。
- 取消、失败和恢复彼此分清。

如果事情不顺：

- 没有当前快照、没有恢复入口、或无法判断做到哪里时，说明运行控制不达标。

主要对应：

- 需求：REQ-DOC-015、REQ-DOC-017、REQ-DOC-018、REQ-DOC-021
- 功能：FUN-DOC-005、FUN-DOC-010

### SCN-DOC-006 模型路线校准

什么时候会发生：

- 原生提取不足，且本次任务明确允许进入 OCR 或视觉模型路线。

人希望发生什么：

- 不同路线在同一输入、同一质量维度下比较。
- 结果明确区分“可用”“不可用”“需要复核”。

如果事情不顺：

- 未授权、不可用、传输失败或质量未过门，都不能假装成“只是还需看看”。

主要对应：

- 需求：REQ-DOC-007、REQ-DOC-013、REQ-DOC-014、REQ-DOC-021
- 功能：FUN-DOC-007、FUN-DOC-008

### SCN-DOC-007 知识库工作副本清洗

什么时候会发生：

- 已验收结果要进入知识库，且用户明确要求去掉低价值整页。

人希望发生什么：

- 只在完整汇合后进行；
- 先预览、再按计划处理、再重建索引；
- 原转换证据和原结果继续保留。

如果事情不顺：

- 只要页数、哈希或完整集合变化，就不能沿用旧计划继续删。

主要对应：

- 需求：REQ-DOC-019
- 功能：FUN-DOC-012

### SCN-DOC-008 下游视觉派生

什么时候会发生：

- 用户另外要求翻译、重绘、风格改写或图片生成。

人希望发生什么：

- 产生明确标记为派生的结果；
- 派生产物不冒充原始来源转换结果。

如果事情不顺：

- 来源结果尚未验收，或授权范围不明时，应直接阻断。

主要对应：

- 需求：REQ-DOC-020

## 四条主要业务链路

### CHAIN-DOC-001 单一来源到交付

当前来源确认 → 内容与关系提取 → 简单/复杂视觉判断 → Markdown 表达 → 资产命名和来源登记 → Unknown 汇总 → 独立验收 → 交付三态

这条链路里，最容易漂移的地方是：

- 用旧上下文补当前内容；
- 把复杂视觉直接压平；
- 跳过独立验收。

### CHAIN-DOC-002 页面修复

第 1 页工作单元 → 页面结构守卫和人工查看 → 第 2–5 页小批量 → 人工复核 → 第 6–total_pages → 确定性合并 → 独立验收

这条链路的重点不是快，而是先小范围证明，再扩大。

### CHAIN-DOC-003 模型校准

确定性候选 → 授权检查 → 相同输入和同一比较面上的候选路线 → 质量/重复性/耗时/资源/成本比较 → 选择、降级或 `unavailable`

这条链路里，`HTTP 200`、模型列表存在或队列接收，只能证明连接或受理，不证明内容和关系理解正确。

### CHAIN-DOC-004 可选下游

已独立验收的 Markdown 或页面单元 → 用户显式选择 → 哈希锁定预览 → 清洗或派生 → 新的独立结果和声明

这条链路永远不能反向改写来源转换的需求、Evidence 或 Verdict。
