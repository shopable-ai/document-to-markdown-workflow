# 文档资产化与 Markdown 转换：项目目标与范围

这份文件是样板项目里最先给人读的业务语义入口。它只回答四件事：

1. 我们到底想解决什么问题。
2. 谁会使用结果。
3. 当前直接交付到底是什么。
4. 什么明确不在当前范围。

如果这里的自然语言和人的理解不一致，应该先改这里，而不是先改工程设计、Workflow、YAML 或代码。

## 这个项目要解决什么

我们希望把当前明确给出的 PPT、PPTX、PDF、图片，以及未来经确认后新增的文档类型，整理成以 Markdown 为主体的独立交付。

这个交付至少要满足：

- 人可以脱离原文件直接阅读和搜索；
- 文字、数字、章节、分区、列表、表格和可确认关系尽量被保留；
- 流程图、图表、漏斗、矩阵、时间线等复杂视觉内容，既有可搜索的 Markdown，也有正文真正引用的视觉证据；
- 看不清、来源冲突、关系不稳或无法确认的部分，会被明确保留为 `Unknown`、`needs-review` 或 `failed`，而不是被猜测补全。

这件事不是“把文字复制成另一个文件”，而是把当前来源的可读内容、结构关系、视觉证据和不确定性都保留下来，并让人能独立复读和独立验收。

## 为什么这件事容易做错

- 页面意义往往不只来自文字，还来自位置、分组、方向、颜色、图例和层级。
- 多个格式相近的文件可能是同一材料的候选版本，也可能根本不是。
- AI 很容易把旧示例、旧上下文或实现细节误带进当前结果。
- 如果只写“转换完成”，人看不出内容哪里可信、哪里还不能用。
- 如果把 Run、测试或历史结果当作最终结论，AI 就会开始用自己的输出证明自己是对的。

## 谁会使用这些结果

### Markdown 读者

他们需要：

- 清楚、可搜索、不过度携带工程噪声的正文；
- 在必要时能看到配套图片，但不被无意义截图淹没。

### 内容与视觉复核者

他们需要：

- 能回到当前页面或当前区域证据核对；
- 能判断哪些已经确认，哪些仍待复核；
- 能直接修改 Markdown 语义，而不必先理解工程 schema。

### 转换执行者

他们需要：

- 清楚知道当前来源、当前范围、当前状态、停止点、恢复点和失败原因；
- 清楚知道什么时候可以继续，什么时候必须停给人。

### 独立验收者

他们需要：

- 事前判据；
- 当前来源指纹；
- 当前包内容；
- 当前 Evidence 与未决项边界。

### 经授权的下游使用者

他们只能消费：

- 已验收的 Markdown；
- 必要且合规保留的视觉资产；
- 明确标记为派生的后续产物。

他们不能反向改写当前来源转换的业务语义。

## 当前直接交付是什么

当前直接交付是：

- 一个当前来源对应一个独立 reader Markdown 包；
- 纯文本结果可以只有 `index.md`；
- 确有必要的复杂视觉证据才进入 `assets/`；
- 正文优先使用语义标题；
- 源文件名、页码、哈希、对象 ID 和 occurrence 进入追溯层，而不是污染读者标题。

当前交付成立，不等于“只要生成一个 `.md` 文件就算完成”。真正的完成至少要求：

- 当前来源被正确绑定；
- Markdown 能独立表达主要内容；
- 必要视觉证据被实际引用；
- 不确定性被保留；
- 结果还能被独立验收者重读。

## 当前范围内包含什么

这个样板项目当前包括：

- 当前来源识别、准入和候选关系确认；
- 文字、结构和关系的保守提取与表达；
- 简单内容与复杂视觉内容的区分；
- 必要视觉资产的提取、最小充分裁切、命名、复制和来源登记；
- Markdown 页面单元组装、分阶段修复和确定性合并；
- Unknown、冲突、失败和恢复；
- 长任务的可观察、可停止和可恢复；
- 独立验收和受限交付声明；
- 用户明确启用时才进入的知识库工作副本低价值整页清洗。

## 明确不在当前范围的事

### NG-001 不从模板、旧示例或常识补写当前来源没有的内容

如果当前来源没说，就不能因为“常见应该这样”而补进去。

### NG-002 不默认建立知识库或把多份材料合成新理论

当前目标是来源转换，不是自动知识建模。

### NG-003 不把翻译、改风格、重绘或视觉生成当成默认转换步骤

这些只能是后续单独授权的派生处理。

### NG-004 不因为已经生成表格、列表或 Mermaid 就删除复杂视觉证据

结构化表达和视觉证据是互补关系，不是二选一替代关系。

### NG-005 不把 HTTP 成功、模型列表、文件存在或 runner 自报完成当成内容正确

这类信号只能证明执行或连接发生过，不能证明需求满足。

### NG-006 不用 Workflow、代码、fixture 或历史 Run 反向定义本文件

这个项目的前期语义权威在 Markdown，不在实现侧。

## 仍待确认的范围边界

当前还没有完全定死的边界包括：

- 多格式文件在什么条件下才算同一逻辑材料候选；
- 在线模型、局域网模型、原图保留和外发的授权边界；
- 未来还支持哪些新文档类型；
- 知识库后置清洗和视觉派生是否属于长期产品范围。

这些问题已经进入 Unknown 台账，但还没有因为 AI 起草而自动升格为已确认范围。
