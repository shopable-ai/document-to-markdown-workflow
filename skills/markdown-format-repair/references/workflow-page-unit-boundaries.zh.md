# Workflow 页面单元修复边界

本参考只在输入属于本项目的 `page-unit`、`document-temp.md` 或 `index.md`，并且任务是在
Workflow 内原位修复时读取。这里的页面标记、证据边界和原位写回规则优先于完整独立文档的
交付规则。

## 适用场景

用户给出单个 Markdown 文件、`page-unit`、`document.md` 或 `index.md`，并要求：

- 清理 AI/OCR 生成的说明性文字、乱码、重复和错序；
- 恢复标题、列表、缩进、层级图、两栏或多分支结构；
- 严格保留所有图片引用与页面注释。

## 先决规则

- 只处理当前明确提供的文件和范围，不扩展到其他页面、证据或来源文件。
- 只做格式修复和结构恢复，不扩写、不总结、不翻译、不补事实。
- 保留 `<!-- page:xx -->`、`---`、标题层级、表格、代码块和其他有结构作用的 Markdown。
- 如果输入是 `page-unit`，图片引用、页面图和读者层边界都必须原样保留。

## 必须保留

- 所有 Markdown 图片引用，尤其是 `![...](<assets/...>)`、路径、文件名、相对路径和数量。
- 图片引用的位置和顺序，除非原文结构已经明确要求移动。
- `Unknown`、`needs-review`、待核对项和其他不确定标记。
- 原有标题层级和页面注释。

## 要清理的内容

- AI 生成的辅助说明、转写说明、复核说明、可检索内容、原始页面图说明、视觉依据说明等非正文文字。
- OCR 噪声、乱码、孤立字符、无意义数字或字母、明显的重复行和重复段落。
- 双重序号、重复列表符号、重复标题和重复节点。
- 只有在上下文和原文足以证明重复时，才删除重复内容。

## 结构恢复

- 双重序号只保留一层。
- 重复列表符号统一成标准 Markdown 列表。
- 思维导图、流程图、层级图和多分支内容，优先恢复父子缩进。
- 两栏或多列内容被挤成同一行时，根据上下文拆回不同父节点和子节点。
- 无法可靠判断的结构不要硬修，保留原文片段并标记 `Unknown`/`needs-review`。

## 工作顺序

1. 先统计并锁定全部图片引用，修复后逐条核对数量、路径、文件名和顺序。
2. 再清理 AI/OCR 噪声、重复和乱码。
3. 再恢复列表、标题和层级关系。
4. 最后检查是否有新增文字、遗漏图片或被误删的正文。
5. 如果仍需人工判断，只留下紧凑的 `Unknown`/`needs-review` 片段。

## 输出要求

- 返回或写回修复后的 Markdown 正文。
- 不输出解释、摘要、JSON 或额外诊断。
- 如果无法保证图片引用完全一致，停止并要求更明确的输入范围。
