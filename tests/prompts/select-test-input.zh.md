# 测试输入选择提示词

将以下候选输入用于“文档资产化与 Markdown 转换”测试前，先判断应选 PPTX、PDF，还是两者对照。

## Prompt

你是文档解析测试设计器。请根据测试目标选择输入格式，不要直接开始解析。

测试目标：验证一个高信息密度文档的原生结构提取、视觉资产保留、PDF 布局提取、OCR 兜底和 Markdown 关系表达。

候选输入：

1. PPTX：适合验证 XML 中的文字片段、形状、分组、连线、坐标、层级和嵌入媒体关系。
2. PDF：适合验证文本块、阅读顺序、边界框、页面渲染和 OCR 对照；但通常不能恢复 PPTX 的原始分组和编辑关系。
3. PPTX + PDF：适合做交叉验证，PPTX 作为结构主来源，PDF 作为页面布局/视觉和文本顺序对照。

选择规则：

- 如果目标只验证原生结构，选择 PPTX。
- 如果目标只验证页面视觉和 PDF 文本布局，选择 PDF。
- 如果目标覆盖本 Workflow A 的完整高质量路径，选择 PPTX + PDF，并明确二者不是重复输入，而是结构层与视觉/布局层的互证。
- 测试页必须使用原文档最后两页（第 24、25 页），禁止使用封面和目录。
- 第 24 页应验证“提升领导力的3357”的多层结构、连线和文字。
- 第 25 页应验证“搞定自己 vs 搞定别人”的对比结构和多层关系。

输出严格包含：

- `selected_input`
- `why`
- `pages_or_slides`
- `expected_capabilities`
- `not_a_valid_test`

推荐答案：

```yaml
selected_input: pptx+pdf
why: PPTX 验证原生结构，PDF 验证视觉布局与文本顺序，两者互证但不互相替代。
pages_or_slides: [24, 25]
expected_capabilities:
  - PPTX XML 文字、形状、分组、连线、坐标和媒体关系
  - PDF 文本块、页面渲染和结构差异
  - 复杂区域视觉资产保留
  - 原生文本与 OCR 候选的分层复核
not_a_valid_test:
  - 只使用第 1、2 页封面和目录
  - 只验证标题是否被提取
  - 用 OCR 结果替代 PPTX XML 和页面视觉证据
```
