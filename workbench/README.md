# 电子书转换工作台 · 开发入口与推进计划

状态：R2 原型保留；R3 只读观察层已实现并通过隔离回归，生产数据对账和真实浏览器联网验收尚未完成。R4 不提前启动。本文不是新的需求权威。

## R3 正式工作台（只读）

从仓库根目录运行（替换为实际已登记的输出根与 collection run ID，不创建转换任务）：

```bash
python3 workbench/server.py --output-root "/actual/registered/output" --run-id "actual-collection-id"
```

浏览器打开 http://127.0.0.1:8765/ 。状态根默认 ~/.codex/background-tasks，可用 --state-root 指定实际已登记位置；--run-id 可重复指定，最多 16 个。仅绑定回环地址，不要对外暴露。退出本服务不会停止转换进程。当前只支持已登记的 PDF 集合，不能直接从文件管理器提交任务。

- GET /api/snapshot：完整只读快照。
- GET /api/events：每 3 秒发送完整快照，重连取最新快照，不回放历史；epoch 与 sequence 区分服务实例和序列。
- 跨路线严格验收总账、实时资源槽占用未取得足够证据时显示 Unknown；当前路线计数不可代替全局验收。
- 入口为 workbench/index.html，须由本地服务提供；preview/index.html 仍是独立 R2 原型。

详细证据、约束及下一轮验收见 [R3 实施与验收报告](R3-REPORT.md)。

## 1. 原始目标

将文档转 Markdown 的正式转换能力变成可独立操作的本地工作台：拖入文件、设置转换参数、查看每本进度、处理失败、管理磁盘和必要图片；关闭网页或 AI 对话不影响后台任务。优先复用现有 Python 转换引擎、正式队列、来源级验收与续跑证据，避免建设第二套转换系统。

- [R2 交互原型](preview/index.html)
- [原型说明与需求差量](preview/README.md)
- [原型历史测试记录](preview/TEST-REPORT.md)

现有原型只处理浏览器文件元数据，所有进度、并发及清理均为模拟。历史 12 项 Chromium 测试通过仅证明已测试的原型交互，不证明生产功能已完成。

## 3. 分阶段推进

| 版本 | 交付 | 通过门 |
|---|---|---|
| R3 | 需求差量核验 + 只读本地状态服务 + 工作台真实进度最小闭环 | 对同一已登记任务，UI 与官方状态、来源总账一致；刷新/断线恢复；不启动、停止、改写或重跑生产任务 |
| R4 | 参数预检、文件提交、正式启动与取消/恢复 | 在隔离小样本上复用正式入口；输入校验、授权、集合锁、幂等控制和续跑测试通过 |
| R5 | 同一正式队列内并发调度 | 先 1，再 2、4；资源槽、内存、磁盘、失败隔离、取消、恢复、结果归属通过；并发收益实测 |
| R6 | 资源统计与安全回收 | 只读文件盘点先行；登记引用、哈希、依赖、锁及重建能力；预览与执行独立；低磁盘和异常中断回归 |
| R7 | 图片识别与性能专项 | 修复未测特征被默认作零的问题；分层样本校准；记录每阶段耗时、模型调用数和误识别；必要视觉不丢失 |
| R8 | 真实批量验收 | 受控新批次与原有质量门对比；来源级严格验收，不以页数 100% 代替完成 |

当前立即任务为 R3-DG 人工决定准备，候选设计见 [R3-D](R3-D-DESIGN-REVIEW.md)，决定唯一入口为[问题与决定记录](../项目治理/问题与决定记录.md)的 R3-DG 小节。未取得明确人工决定前 C08 不完成，C09/C18/C22 不建立；按治理满足相应人工门并取得许可后，下一工程任务才是 R3.1 生产只读对账（V4/V5），随后隔离技术 Demo。R3 不实现物理清理、并发扩容或真实任务写操作；通过真实验收门后才进入 R4。

## 4. R3 实施细节与验收清单

1. 先读 [AGENTS](../AGENTS.md)、[后台任务说明](../references/pdf-background-task.zh.md)、[长任务契约](../contracts/long-task-interaction.yaml)、[后台管理器](../adapters/pdf_background_task.py)、[资源槽](../adapters/pdf_resource_slots.py) 的有关最小范围，记录现有字段、语义、锁及未知项；不重做转换引擎。
2. 建立本地只读适配层。优先复用官方状态语义、当前快照、已登记集合和独立验收总账；注意官方 status 在部分异常情形可能写入生命周期状态，活动队列只读接入须核实边界，不能把该命令一概视为纯读取。历史数据不冒充实时状态，来源不可见则 Unknown。默认仅绑定回环地址，访问路径白名单，禁止任意命令执行和文件读取。
3. 建议先使用 Python 本地服务与原型前端实现最小闭环；HTTP GET 返回快照，SSE 或等价机制只发送精简状态变化。断线后重新取权威快照，区分更新序列、任务 ID、数据时间和连接状态。后台服务不得依赖页面持续连接。无实际测量不显示虚构 ETA；没有页级记录不显示虚构百分比。
4. 原型和正式界面分离：保留 preview/index.html，不将模拟数据写进真实状态。正式运行模式不能显示模拟容量，尚不支持的并发/暂停/清理操作禁用并说明原因。真实页面的待处理、正在处理、等待资源、待复核、失败、严格通过均可区分。
5. 测试覆盖：同一任务快照与 UI 对账、空数据、旧快照、状态未知、连接中断/恢复、同名不同源、原生与混合路线、页处理结束但验收未通过、关闭界面不影响任务；并证明只读服务未改动活动任务清单、工程包与状态证据。测试优先使用隔离夹具，不对正在运行的任务施加测试性故障。

## 5. 生产安全边界

- 不为工作台另开活动生产队列、不重启或迁移活动队列、不修改其冻结来源清单与运行目录；不通过四个 CLI 进程规避现有集合锁。
- 目前正式集合逐本串行，local-pdf 与 visual-model 资源槽各为 1；扩容须另行实现和验证。
- 已有运行任务继续沿用其登记 ID 和参数；导出以跨路线来源级严格验收总账为准。历史 74 本批次状态不在此计划中固化，必须从真实证据读取。
- 文件清理必须遵守现有资产契约，先区分读者层图片与工程缓存。未确认依赖、来源、哈希或再生能力的文件保留；未经批准不得物理删除。
- 只报告本轮真正实现、测试与提交的成果；原型设计自评不当作第三方评审或生产验收。
