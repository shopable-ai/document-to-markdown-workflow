# 电子书转换工作台 · 交互原型 R2

## 原始目标

通过一个本地网页入口配置电子书转换、观察每本进度、管理等待顺序及资源；继续复用既有 `pdf_background_task.py`、正式集合队列和严格验收机制。

## 打开方式

浏览器打开 `index.html`。无构建、无外部网络请求、无真实转换 API。文件选择和拖入仅读取浏览器提供的文件元数据，页面状态刷新后重置。

## 本轮交互

- 移除顶部大段演示说明，保留页脚的简短原型标识。
- 主界面与配置界面均支持多 PDF 拖放/文件选择；过滤非 PDF、选择列表重复项；允许移除未提交文件。
- 活动批次继续执行；追加文件进入独立待提交批次，不更改已冻结的来源清单，不开启第二个生产队列。
- 等待任务可拖动排序，并提供上移/下移按钮；运行中、正在验收、终态任务不可拖动。调度优先级按新等待顺序。
- 当前批次执行结束后可手动启动下一批；上一批的每本验收结果继续在历史中展示（原型不提供跨批复核执行）。
- 区分用户设置最大并发与示例资源容量、实际并发；页数完成和严格验收分离。

## 需求差量（待确认）

| 工作包 | 需求 | 功能与验收 |
|---|---|---|
| WB-01 | 低成本提交转换任务 | 多文件拖入、配置、预检、拒绝非法输入；不丢失活动任务 |
| WB-02 | 等待任务优先级可调整 | 稳定任务 ID；仅重排等待项；不改变源清单或既有证据 |
| WB-03 | 活动期间可继续提交 | 新增独立待提交批次；原队列锁不变；前一批终止后才允许下一批启动 |
| WB-04 | 状态透明 | 每本阶段、页数、验收、并发资源、异常及历史记录 |
| WB-05 | 资源治理 | 安全清理预览、保护来源及依赖资产 |

这些是原型工作包编号，不是现有 R01–R11 的正式新编号。待用户确认后，增量更新中文权威需求说明、需求树及功能树。

## 验收与实现边界

独立 HTML 已在 Chromium 通过 12 项自动化交互检查（见 `TEST-REPORT.md`）；浏览器对 file:// 导航有限制，测试用 set_content 加载同一 HTML 的完整内容。真实本机文件访问、SSE、后端预检、实际转换、多本并发、任务持久化、物理清理均未接入。真实 PDF 队列目前逐本串行，资源槽容量固定为 1；原型容量 2/4 为示意。生产接入应先只读状态、再任务控制、最后在隔离环境验证并发。现有严格验收和生产队列不受本原型修改影响。
