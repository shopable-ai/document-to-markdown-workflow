# Workflow B 验收

## 必须通过

- [ ] 输入是一个明确的 Markdown 局部知识单元，而不是整份文档的无界文本。
- [ ] 已记录视觉用途、主结构、节点/层级和信息密度决策。
- [ ] 参考资产有来源和用途；未提供参考资产时流程仍可独立运行。
- [ ] 生成请求包含文字保真、画布比例、风格、禁用项和事实边界。
- [ ] 成功输出恰好一张 raster 图片，不生成 PPTX、PDF、SVG 或批量文件。
- [ ] 图片中的核心文字可读，结构与 Markdown 的事实和关系一致。
- [ ] 请求 manifest 不包含 API key、Authorization、Cookie 或供应商秘密。
- [ ] 失败时返回可诊断状态；过密内容返回 `needs-split` 而不是强行生成。

## 人工复核重点

- 是否一眼看出主题和阅读方向；
- 是否存在模型臆造的事实、数字或关系；
- 是否为了“好看”牺牲了文字可读性；
- 参考资产是否被误用为未经授权的复制模板。
