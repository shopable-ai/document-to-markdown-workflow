# AI 协作与文档驱动

## 项目背景

这是一个由人工在 Codex 对话中表达目标、纠正边界和确认基线，由 AI 负责检索、分类、推导、落盘、实现与验证的 AI-native 项目。对话提示词是推进输入，仓库中的人工可读 Markdown 是可持续维护的语义载体。

## 人工职责

- 提供原始意图、业务边界、样例、反例和纠正。
- 决定阻断型 Unknown、冲突取舍和候选关系。
- 在 C08 阅读、讨论、纠正和决定，并明确是否建立 C09 业务范围基线、C18 完整需求基线和 C22 架构基线。
- 复核独立 Verdict，决定是否接受交付和最终架构承载位置。

人工不需要编辑 YAML、schema 或复杂机器字段。稳定编号用于讨论、链接和追溯；编号可以由 AI 维护，但不得替代自然语言语义。

## AI 职责

- 忠实保存人工表达，区分 Fact、Inference、Unknown 和 Conflict。
- 先建立文件和标题框架，再逐项填充已经有来源的内容。
- 检查遗漏、重复、职责混写、越过阶段门和旧内容污染。
- 在人工基线之后把 Markdown 单向投影为设计、Spec、任务、Workflow、Skill、Contract、代码和测试。
- 发现冲突或证据不足时停止在相应阶段，返回权威文件，不自行补写答案。

## Markdown-first 顺序

```text
人工表达
→ 人工可读 Markdown 草稿
→ 人工确认的 Markdown 基线
→ 机器可读投影
→ 实现与验证
→ 运行证据和独立结论
```

YAML、Contract、Workflow、代码和测试只能从已确认 Markdown 投影。当前阶段已有机器文件属于 Brownfield 资产，不得反向生成需求。

## Codex 提示词驱动入口

一次推进提示词至少说明：

1. 当前项目和工作目录；
2. 当前阶段与目标；
3. 允许修改、只读和禁止修改的范围；
4. 需要读取的人工来源；
5. 本批次输出文件及其唯一职责；
6. 必须保留的 Unknown、冲突和用户资产；
7. 验证方法、停止条件和不得声称的内容。

提示词本身不是长期权威。稳定结论必须进入相应 Markdown；一次性提示词只保存在 `.prompt/`，不得占据项目入口。

## 标准推进循环

```text
读取当前 Goal 与阶段
→ 核对工作树、权威文件和冻结范围
→ 建立或检查文件框架
→ 填入有来源的内容
→ 反方检查遗漏、重复、越界和漂移
→ 执行与当前阶段相称的验证
→ 记录 Unknown 和返回位置
→ 到人工门时停止
```

## 防漂移规则

- 一种语义只维护一个权威正文；导航、树和矩阵只链接，不复制完整正文。
- 旧文件、代码行为和历史运行只能提供盘点证据，不能覆盖最新人工纠正。
- 工程术语不得进入业务目标；治理状态不得占据项目业务首屏。
- 一个文件出现两个以上生命周期对象时，先检查是否需要拆分。
- 无法确认的内容保留 Unknown；不得为了让框架完整而猜写。
