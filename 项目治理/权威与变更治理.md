# 权威与变更治理

本文件规定当前项目中什么可以定义语义、什么只是投影或证据，以及上游变化后怎样传播失效。它不批准任何业务或架构基线。

## 权威层次

| 层次 | 当前权威 | 允许的派生 | 禁止的反向影响 |
|---|---|---|---|
| 业务语义 | 人工确认过程中的 `项目需求/` 中文 Markdown | 需求树、追溯索引、后续机器需求投影 | 代码、测试、Contract、Workflow、历史 Run 生需求 |
| 当前项目治理 | `项目治理/` 中文 Markdown | 检查表、状态索引 | 通用参考覆盖当前项目边界 |
| 架构与工程 | C18 完整需求基线和 C22 架构基线后形成的中文方案、设计、Spec 和任务 | YAML、schema、Workflow、Skill、代码、测试 | 候选或旧实现自动升级为基线 |
| 运行观察 | 当前 Controlled Run 的不可变 Evidence | 独立 Verdict、受限交付 | 历史 Run、fixture 或日志摘要冒充当前 Evidence |
| 交付声明 | 有效 Verdict 支持的 Delivery 和 Bounded Claim | 对外摘要 | 超出 Evidence 范围的能力声明 |
| 历史与参考 | `archive/`、旧英文目录、既有通用治理材料 | 迁移对账和 Brownfield 盘点 | 直接参与当前路由或审批 |

## 人工纠正与基线

- 基线前：最新明确人工纠正优先于较早人工材料，冲突必须记录。
- 基线后：新的人工纠正是变更输入，不静默改写已确认基线；先标记受影响对象，再重新确认。
- AI 推导不能覆盖人工表达；无法判断优先级时保留 Conflict 或 Unknown。
- “文件较新”“代码正在运行”“测试通过”都不是语义优先级。

## 生命周期状态

| 状态 | 含义 |
|---|---|
| `draft` | 可阅读、可修改，尚未人工确认 |
| `candidate` | 可比较的方案或工程候选，尚未成为基线 |
| `confirmed` / `baselined` | 已由相应人工门明确确认 |
| `derived` | 从权威对象生成，不允许独立修改语义 |
| `active` | 当前允许执行或引用的版本 |
| `stale` | 上游已变化，需要重新核对但尚未判定不可用 |
| `invalidated` | 已知不能继续支持下游使用或声明 |
| `retired` | 被明确排除，不再进入活跃链路 |
| `archived` | 只读保留，不参与当前路由 |

文件存在不等于 `confirmed`，测试通过不等于 `active`，历史评分不等于当前 Verdict。

## Markdown 到机器投影

机器投影只能在相应人工门之后生成。每个活跃 YAML 必须声明或可解析到：

```yaml
id:
version:
human_reference:
```

机器派生索引必须包含来源、哈希、生成时间、生成器版本和不可手改标记。Markdown 与 YAML 冲突时停止并标记 `contract-doc-drift`，不得静默选择任意一方。

## 变更流程

```text
收到人工纠正或发现事实变化
→ 定位唯一上游权威对象
→ 记录变化、原因、Unknown 和冲突
→ 计算受影响的下游对象
→ 标记 stale 或 invalidated
→ 返回相应 C 节点重新确认/设计/实现/测试
→ 生成新的 Evidence 和 Verdict
→ 才能恢复 Delivery 与 Claim
```

## 失效传播

| 上游变化 | 至少检查的下游 |
|---|---|
| 原始意图、范围或非目标 | Requirement、场景、验收、设计、Spec、任务、运行与声明 |
| Requirement | 验收、追溯、设计、Spec、任务、Workflow、测试、Evidence、Verdict、Delivery、Claim |
| Acceptance | 验证设计、测试结果、Evidence、Verdict、Delivery、Claim |
| 架构或 Spec | 任务、Workflow、Skill/Tool、代码、测试、运行证据 |
| Workflow/实现 | 测试、Release Readiness、Controlled Run、Evidence |
| Evidence 身份或新鲜度 | Verdict、Delivery、Claim |

下游重新生成不能自动关闭上游变更；必须证明重新确认、重建和复测已经覆盖受影响范围。

## 双权威处理

发现两个文件都在定义同一语义时：冻结二者的进一步扩写；确定当前人工可读权威；把另一份标为 reference、candidate、derived、retired 或 archived；修复所有入口；再做内容迁移对账。不能通过复制“保持同步”来长期维持双权威。
