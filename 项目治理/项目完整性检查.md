# 项目完整性检查

这个文件帮助人判断项目有没有漏掉关键环节。第一次阅读不需要理解 U01—U24 编号，先看下面五个问题。

## 先回答五个普通问题

1. 人真正要什么，是否已经直接写进项目目标和需求。
2. 需求是否有来源、例子、反例、未知和冲突，而不是由代码反推。
3. 已有 Workflow、Skill、Contract 和代码是否逐项支持确认后的需求。
4. 一次实际运行是否产生了足以独立判断的证据。
5. 需求或实现变化后，旧证据和旧结论是否会被正确判为失效。

当前只能较完整回答前两个问题；后三个问题要在后续基线、Brownfield 盘点和实际运行中验证。

## 使用规则

- 这个表只指出去哪里检查，不复制各文件的正式答案。
- 文件存在不等于检查通过。
- 工程资产可运行不等于业务需求已经确认。
- 检查失败时返回最早出错的文件，不在下游补写。
- U-B01、U-B02 在人工明确决定前持续保持开放。
