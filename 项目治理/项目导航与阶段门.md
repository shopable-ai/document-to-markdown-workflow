# 项目导航与阶段门

这个文件只说明项目走到哪里、下一步允许做什么。普通人不需要背诵 C01—C40；编号用于返回和追溯。

## 当前在哪里

当前处于“整理并核对前期需求”的阶段：

```text
原始请求
→ 目标和范围
→ 事实、推导、未知和冲突
→ 需求正文
→ 样例与反例
→ 需求树
→ 等待人工阅读、讨论、纠正和决定
```

现在没有建立任何业务或架构基线。

## 四个人工节点

| 节点 | 人实际要做什么 | 形成什么结果 | 解锁什么 |
|---|---|---|---|
| C08 | 阅读、讨论、纠正并明确决定 | 人工决定记录 | 允许判断是否可建立 C09 |
| C09 | 固化已经确认的业务范围 | 业务范围基线 | C10—C17 的场景、功能、行为和验收 |
| C18 | 固化完整需求、行为和验收 | 完整需求基线 | C19—C21 的存量盘点、方案和架构 |
| C22 | 固化方案和架构 | 架构基线 | 工程设计、规格、任务和机器投影 |

C08 是人的活动，C09、C18、C22 是活动产生的不同基线，不能合并成同一个编号。

## 完整生命周期

| 区段 | 普通含义 | 主要结果 |
|---|---|---|
| C01—C07 | 搞清楚人要什么 | 可人工阅读的需求草稿 |
| C08—C09 | 人确认业务边界 | 业务范围基线 |
| C10—C18 | 补齐场景、功能、行为、质量和验收 | 完整需求基线 |
| C19—C22 | 核对旧资产、比较方案、确定架构 | 架构基线 |

完整节点说明保留在[既有生命周期参考](../PROJECT-DELIVERY-WORKFLOW.md)，该文件不是当前业务权威。

## 当前允许

- 修正 C01—C07 的中文需求和来源证据。
- 补充当前确实有内容的治理文件。
- 只读核对现有 Workflow、Skill、Contract、代码、测试和历史运行。
- 运行链接、结构、规格包和布局验证，确认文档修改没有破坏现有工程。

## 当前禁止

- 把 C08 写成已经完成。
- 建立 C09、C18 或 C22 基线。
- 创建或填写 C10 以后的业务正文。
- 修改机器契约、Workflow、Skill、代码或测试。
- 用“工程可以运行”替代需求确认。
- 生成空 Run、Evidence、Verdict、Delivery 或 Claim。

## 出错时回到哪里

| 发现的问题 | 返回文件 | 为什么停下 |
|---|---|---|
| 人的原话遗漏或被改写 | 项目需求/需求发现/原始请求.md | 后续推导没有可靠来源 |
| Fact、Inference、Unknown、Conflict 混淆 | 项目需求/需求发现/需求发现记录.md | AI 结论可能冒充人工事实 |
| 项目目标、范围或非目标错误 | 项目需求/项目目标与范围.md | 不能建立业务范围基线 |
| R01—R11 有遗漏、冲突或难以理解 | 项目需求/需求说明.md、样例与反例.md | 不能进入 C08 决定 |
| 需求树增加了新语义 | 项目需求/需求树.md | 树只能组织需求 |
| 旧实现与需求不符 | 后续 C19 存量资产与差距 | 不能让旧实现改写需求 |
| 证据不支持结论 | 后续验收、Evidence 或 Verdict | 不能继续交付和声明 |
