# 项目需求说明

这个文件是当前项目的需求入口摘要，直接回答“转换结果必须做成什么样”。详细目标和范围只在[项目目标与范围](项目目标与范围.md)维护，R01—R11 的完整条件只在[需求说明](需求说明.md)维护；本文件让人先看懂核心需求，不另立第二套编号或细节权威。

## 核心需求概要

### 1. 完整转换指定文档范围

项目必须把用户指定的页码范围或完整文档端到端转换成一个连续结果。每个应处理的页面或内容单元都要有明确去向，不能漏失、重复、错序，也不能用少量页面成功、一个文件外壳、摘要或工程中间产物代替完整转换。

### 2. 保留内容、结构和原意

结果要尽量保留文字、数字、章节、标题层级、页面分区、段落、列表、表格、公式、代码、跨页连续性和能够确认的关系。Markdown 要按来源实际结构组织成可直接阅读和搜索的文档；轻度整理只能修复转换造成的表达问题，不能摘要、扩写、删减、翻译或改变原意。

### 3. 保住复杂视觉表达的含义

流程图、矩阵、图表、漏斗、时间线、树状图、关系网络、复杂公式排版和信息图等内容，不能被扁平 OCR、摘要或猜测文字替代。Markdown 要保存可确认的标签、数值和关系；在 U-B02 允许时，还要随附最小充分的静态视觉依据，保留空间、方向、层级、颜色、图例和整体布局供人工核对。简单文字已经可靠表达后，不保留无价值截图；照片或扫描图中已经可靠转写且没有额外视觉作用的文字区域，可以裁掉，但不能裁掉仍承载关键布局、图形或关系的部分。

### 4. 交付可复制、可移动的最终结果包

正式结果以 `index.md` 为主体，并在需要且获准时包含正文实际引用的静态图片。图片使用包内相对链接；复制、移动或解压整个结果包后仍能阅读和复核。读者不应依赖临时绝对路径、工程缓存、原始编辑软件、模型响应或历史输出才能使用结果。

### 5. 让结果可复核且不过度

无法确认的文字、数字、结构和关系必须保留为 `Unknown` 或 `needs-review`。冲突、失败、未覆盖范围和实际处理页码要真实可见；技术命令成功、文件生成或局部页面通过，不能单独证明整份文档正确或完成。

### 6. 保持当前来源和多来源边界

新结果只能包含当前指定来源能够支持的内容，不能混入旧示例、历史输出、固定模板或其他材料。多个来源默认分别转换；只有用户明确声明它们是同一逻辑文档的候选版本时才比较。来源隔离是保证结果可信的重要约束，但不取代前五项核心价值。

以上六项对应[需求说明](需求说明.md)中的 R01—R11，并按业务价值而不是工程执行顺序排列。

## 项目不负责什么

项目在可信、完整、可用、可复核的 Markdown 结果包交付处结束，不负责知识库、内容整理、检索问答、多材料组合、图片生成、视觉重绘或其他下游 AI 工作。R12“知识库低价值页清洗”保持退役，编号不得复用。

## 普通阅读顺序

第一次阅读只需要看四个文件：

1. [项目目标与范围](项目目标与范围.md)：项目做什么、为谁做、在哪里结束。
2. [需求说明](需求说明.md)：结果必须满足的 R01—R11。
3. [样例与反例](需求发现/样例与反例.md)：哪些结果方向正确，哪些明显错误。
4. [需求树](需求树.md)：把已经存在的需求按主题组织起来。

要追查人的原话、AI 推导、历史迁移或仍未回答的问题，再进入[需求发现](需求发现/说明.md)。

## 仍需人工决定

- U-B01：PDF、PPTX 之外还接受什么正式来源；独立图片是否为同级输入。
- U-B02：原图和截图的保存、发布及替代交付边界。

这两个问题继续开放，不能由历史材料、当前代码或 AI 推导自行关闭。

## 每个文件负责什么

| 文件 | 负责回答 | 不能代替什么 |
|---|---|---|
| `项目目标与范围.md` | 为什么做、做什么、不做什么 | 不展开实现路线 |
| `需求说明.md` | 完整转换、内容结构、复杂视觉、可携带结果包、真实边界和来源约束必须满足什么 | 不记录 AI 推导过程或运行步骤 |
| `需求树.md` | R01—R11 怎样按主题组织 | 不产生新需求，不表示工程顺序 |
| `需求发现/原始请求.md` | 人实际说过什么 | 不保存 AI 结论 |
| `需求发现/需求发现记录.md` | Fact、Inference、Unknown、Conflict | 不成为第二份需求正文 |
| `需求发现/样例与反例.md` | 用例子解释需求边界 | 不冒充正式验收样本 |
| `需求发现/历史材料迁移对账.md` | 旧材料的去向和失效 | 不让旧材料恢复为当前权威 |

## 需求怎样形成

```text
人的原始表达
→ 保存原话
→ 区分事实、推导、未知和冲突
→ 写成目标、范围和需求草稿
→ 用样例和反例检查是否容易误解
→ 人工阅读、讨论、纠正和决定
```

C01—C07 只是这条过程的追溯编号。普通阅读不需要先理解编号。

## 当前阶段边界

当前只完善原始请求、目标范围、需求发现、需求正文、需求树和样例。人工决定尚未发生，也没有建立业务范围基线、完整需求基线或架构基线。

业务场景、能力与功能、行为状态与时序、验收判据等后续正文，需要在人工确认业务范围后根据决定创建；当前不创建空文件。
