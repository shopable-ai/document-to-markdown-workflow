# 项目需求说明

## 本目录负责什么

本目录承载当前“文档转 Markdown”项目的业务目标、业务需求、需求组织和需求来源记录。当前业务语义必须在这里直接成立，不能依赖归档、Contract、Workflow、代码、测试或历史 Run 补充。

这里不重复完整业务内容。项目做什么、输出什么、结束在哪里，见[项目目标与范围](项目目标与范围.md)；转换结果必须满足什么，见[需求说明](需求说明.md)。

## 需求形成顺序

```text
C01 用户原始表达
→ C02 原始请求记录
→ C03 项目目标与范围
→ C04 事实、样例、反例、冲突与 Unknown
→ C05 AI 需求发现与对象分类
→ C06 业务需求叙事
→ C07 需求列表与需求树
→ C08 人工业务确认
```

前一节点没有形成可读内容时，后一节点不能用空文件、代码行为或历史运行结果代替。当前只处理 C01—C07。

## 普通业务阅读顺序

1. [项目目标与范围](项目目标与范围.md)：先判断项目为什么存在、处理什么、不处理什么。
2. [需求说明](需求说明.md)：再检查转换结果必须满足的具体要求。
3. [需求树](需求树.md)：最后查看这些需求之间的组织关系。

需要核对原话、AI 推导、冲突或迁移依据时，再进入[需求发现说明](需求发现/说明.md)。返回项目入口见[项目说明](../项目说明.md)。

| [`../项目说明.md`](../项目说明.md) | 说明当前具体项目、输入、输出、核心要求、结束边界和阅读入口 | 不展开完整需求、治理或工程方案 |

| [`需求说明.md`](需求说明.md) | 保存 R01—R11 的具体业务要求和退役编号记录 | 不保存 AI 推导过程、实现路线或正式测试步骤 |
| [`需求树.md`](需求树.md) | 组织并回指已经存在的活跃需求 | 不产生新需求，不表示工程顺序 |

| [`需求发现/需求发现记录.md`](需求发现/需求发现记录.md) | 保存 Fact、Inference、Conflict、Unknown、排除项和迁移对账 | 不成为第二份业务权威，不保存当前运行状态 |

## 业务权威与来源边界

- 当前规范业务语义只在 `项目目标与范围.md` 和 `需求说明.md` 中维护。
- `需求树.md` 只组织活跃需求，不增加或修改需求语义。
- `原始请求.md` 和 `需求发现记录.md` 保存来源与推导证据，不覆盖规范业务正文。
- 既有人类材料中的有效业务内容必须直接进入当前文件；代码、YAML、Contract、Workflow、测试和历史 Run 不能反向产生业务需求。

## 后续文件的锁定边界

`三次基线.md`、后续场景、功能、行为、状态、时序、验收和追溯文件，以及全部方案、设计和工程文件当前保持锁定；本阶段不创建、不修改，也不描述为已经完成。C08 人工确认后，才允许按 V1 边界继续。
