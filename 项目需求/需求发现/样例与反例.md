# 样例与反例

本文件用容易理解的例子解释 R01—R11 的边界。这里的例子来自当前人工要求和历史材料对账，是需求理解辅助，不是已经执行过的验收样本。

## 正确方向

### 完整文档形成连续结果

用户指定转换整份 PDF。结果按原顺序覆盖全部应处理页面和章节，正文、列表、表格、公式、代码和跨页内容连续组织；每个页面或内容单元都有明确去向，没有用前几页成功代替整份文档完成。

对应需求：R01、R02、R03。

### 内容与结构都能直接使用

一份多栏、含表格和章节层级的文档被转换后，读者能够顺着标题、段落、列表和表格连续阅读与搜索，不需要自己把散乱 OCR 行重新拼成文档。

对应需求：R02、R03、R04。

### 当前来源得到独立结果

用户指定一个 PDF，结果只表达这个 PDF 中能够确认的标题、正文、数字、列表、表格和关系。旧文件中的标题和内容不会进入新结果。

对应需求：R10。

### 简单文字直接写成 Markdown

一页只有标题、段落和普通列表，而且文字顺序能够可靠确认。结果直接使用标题、段落和列表，不把整页截图放进读者结果。

对应需求：R02、R03、R06。

### 扫描图只保留有视觉价值的部分

一张扫描页中的正文已经可靠转写到 Markdown，边角上的重复文字不再提供布局、图形或核对价值；结果可以从随附图片中裁掉这些冗余区域，同时保留印章、手写标记、表格线、方向和其他仍然需要人工核对的部分。

对应需求：R05、R06、R07、R08。

### 复杂图示同时可读和可核对

来源中有流程图、矩阵或带图例的统计图。Markdown 写出能够确认的节点、标签、数字和关系；如果 U-B02 确认允许交付视觉资产，再保留足以核对空间关系、颜色或图例的最小来源视觉依据。

对应需求：R04、R05、R07。

### 结果包复制后仍然可用

Markdown 正文引用必要静态图片时使用包内相对路径。把整个结果包复制到另一个目录后，`index.md` 仍能打开图片；读者不需要寻找临时页面渲染目录、模型输出或原工作区才能理解文档。

对应需求：R02、R08。

### 看不清的部分保留未知

某个数字或箭头方向无法从来源可靠确认。结果保留已经确认的部分，并明确标记 `Unknown` 或 `needs-review`，不补造完整关系。

对应需求：R09。

## 明显错误方向

### 只转换一部分却声称整份完成

一百页文档只有前几页形成 Markdown，或漏页、重页、错序，但结果仍用“已转换”概括整份文档。

错误原因：指定范围没有完整覆盖，违反 R01、R09。

### 使用旧内容填充新结果

新文档没有某个章节，但转换结果因为旧模板或上一份输出而自动补出该章节。

错误原因：污染当前来源，违反 R10。

### 只生成文件外壳

结果只有固定标题、页码占位、元数据或少量摘要，读者仍然需要打开原文才能知道主要内容。

错误原因：不能独立阅读，违反 R02。

### 只保留散乱识别文字

多栏、表格、卡片或流程内容全部被压成无层级的文字序列，原有分区和关系消失。

错误原因：结构和关系没有保留，违反 R03、R04。

### 正文依赖临时工程目录

Markdown 中的图片链接指向原机器绝对路径、临时页面目录或工程缓存；复制结果包后图片全部断链。

错误原因：没有形成可携带的最终结果包，违反 R08。

### 复杂图示只剩图片

结果只插入一张流程图截图，没有可搜索的标题、节点或文字。

错误原因：不能搜索，违反 R05。

### 复杂图示只剩推测文字

结果删除原图，并根据模糊识别结果猜出箭头、层级、颜色含义或因果关系。

错误原因：既失去核对依据，又制造确定性，违反 R05、R09。

### 把整张扫描图一律删除

扫描图里的正文已经写入 Markdown，就把整张图片删除，连同印章、手写标记、表格布局或无法识别的关键区域一起删掉。

错误原因：裁切范围超过冗余文字，丢失仍有复核价值的视觉内容，违反 R06、R07、R09。

### 自动把两个来源合并

PDF 和 PPTX 文件名相似，系统没有得到用户授权就把二者配对、选主或合并。

错误原因：违反 R10。

### 静默修正来源原有文字

来源文档本身有一个疑似错字，转换过程没有保留原文或标记疑问，直接把它改成 AI 认为正确的写法。

错误原因：改变来源，违反 R10、R11。

## 容易混淆的边界

| 情况 | 当前处理方向 | 仍需确认的地方 |
|---|---|---|
| 用户只指定部分页码 | 只要求指定范围完整覆盖，并明确实际页码 | 后续验收怎样记录遗漏、重页和额外页 |
| 文档内图片只承载清晰的短文字或普通列表 | 文字可靠写入 Markdown 后可不进入读者资产 | 必须先确认图片不承载空间或颜色关系 |
| 图中同时有文字和布局关系 | Markdown 表达文字；获准时保留视觉依据表达布局 | U-B02 尚未决定资产发布边界 |
| 页面渲染只用于识别或检查 | 保留在工程证据，不自动进入读者结果 | 读者是否需要它取决于语义核对价值和授权 |
| 多个相似来源 | 默认分别转换 | 只有用户明确声明候选关系才比较 |
| 独立图片作为输入 | 当前不自行决定 | U-B01 |
| 原图或截图随结果发布 | 当前不自行决定 | U-B02 |
| 转换产生的识别错误 | 可以依据来源修正 | 必须能回到来源核对 |
| 来源本身的疑似错字或矛盾 | 保留原文并标记待复核 | 不能静默替作者改写 |

## 尚缺的真实样本

## 人工检查

人工阅读本文件时只需回答：

1. “完整转换”和“可用结果包”的例子是否符合项目真正价值。
2. 内容、结构和复杂视觉保真的正确方向是否符合期望。
3. 错误方向是否确实应该拒绝。
4. 是否还存在会导致实现误解的边界情况。
5. U-B01、U-B02 是否继续保持未决定。
