# 需求发现记录

本文件只记录 AI 形成的 Fact 分类、Inference、Conflict、Unknown 和排除项；业务目标与需求已写入对应文件，不在这里复述。旧人工材料的哈希和逐节迁移证据见[历史材料迁移对账](历史材料迁移对账.md)。

## 当前分析输入

| 输入 | 身份 | 用法 |
|---|---|---|
| 当前人工原话与纠正 | C01—C02 的直接输入 | 决定最新业务边界和返工方向 |
| `GOAL.zh.md`、`TASK-TREE.zh.md` | 历史人工材料 | 通过迁移对账核查遗漏，不作为原始请求或当前权威 |

| 代码、测试、Workflow、Contract、历史 Run | Brownfield 工程和运行材料 | 只做盘点，不反向生需求 |

## 分类总表

| 类别 | 当前含义 | 现阶段用途 |
|---|---|---|
| 业务目标 | 指定范围端到端完整转换、内容与结构保真、复杂视觉保真、可携带结果包、可复核交付 | 进入 `项目目标与范围.md` |
| 活跃业务需求 | R01—R11 的具体转换要求 | 进入 `需求说明.md` |
| 质量或验收约束 | 能否看懂、能否核对、能否保留不确定性 | 进入 `需求说明.md` |
| 项目治理 | 文件分工、阅读顺序、权威边界 | 进入 `项目需求/说明.md` |
| 成熟既有能力 | A1—A7、原生提取、视觉处理、页面单元、可携带包、批量/恢复和独立验收 | 证明项目不是从零开始；进入工程资产索引，后续 C19 按需求核对 |
| 候选工程设计 | OCR、模型、SSH、命令、适配器、YAML 字段 | 先保留为推导或后续工程内容，不进当前需求正文 |
| 历史运行状态 | 旧 Run、旧页面状态、旧结果包 | 只读历史，不进入长期需求 |
| 已被最新纠正排除 | 内容整理者、知识库、视觉重绘、自动候选配对 | 记为排除项，不再回写为需求 |

## C08 待确认

当前仍停在 C01—C07；C08 只记录为后续人工确认点，不在本文件展开。

需要人工确认的点：

1. 独立图片是否成为正式输入类型，还是仅作为文档内资产或附属证据。
2. 来源原图、来源截图和技术性临时渲染的保存、发布与替代交付边界。
3. 复杂视觉与简单文字的判定边界是否还需要更细正反例。
4. 图片命名、`assets/` 目录和追溯字段是否还有额外硬约束。
5. 什么时候才允许把两个文件视为候选版本，而不是独立来源。
6. 哪些 Unknown 会阻断 C09 业务范围基线，哪些只在 C10—C17 继续补充。
