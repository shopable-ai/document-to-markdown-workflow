# 需求树

本树只组织 `需求说明.md` 中已经存在的 R01—R11，不增加需求，也不表示工程执行顺序。

如果只想判断需求方向是否正确，先读[需求说明](需求说明.md)开头的五项判断和[样例与反例](需求发现/样例与反例.md)；本树只用于快速查找。

## 根目标

把用户指定的文档范围端到端转换成可信、完整、可用、可携带且可复核的 Markdown 结果包。

## 一、完成完整文档转换

- R01 指定文档范围必须完整转换并形成可用结果。
- R02 Markdown 必须内容连贯、结构清楚并可独立使用。

## 二、保留内容、结构和原意

- R03 文字、数字和文档结构必须尽量保留。
- R04 可确认的关系必须得到表达。
- R11 只允许不改变原意的轻度整理。

## 三、保住复杂视觉语义

- R05 复杂视觉必须同时可搜索、可核对。
- R06 简单文字内容不保留无价值截图。
- R07 必要视觉依据必须完整且最小充分。

## 四、形成可携带的读者结果包

- R08 Markdown 与必要资产必须便于阅读和携带。

## 五、让结果可复核且不过度

- R09 Unknown、冲突和失败必须如实保留。

## 六、约束当前来源和多来源关系

- R10 当前来源必须隔离，多个来源默认分别转换。

R10 是保证结果可信的运行边界。它不改变前五组所表达的核心业务价值，也不应重新成为根目标。

## 边界声明

完整语义只在 `需求说明.md` 中维护。本树不得补充条件、验收、因果、优先级或新编号。
