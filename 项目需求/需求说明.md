# 需求说明

本文件是当前项目的活跃需求正文草稿，集中表达等待人工阅读、讨论、纠正和决定的业务要求。

## 业务需求叙事

来源文档的含义不只存在于文字，还可能存在于章节顺序、标题层级、页面分区、列表、表格、公式、代码、图表、箭头、颜色、位置和图形组合中。项目需要把用户指定的完整范围端到端转换成真正可用的 Markdown 结果包，同时保留能够确认的内容、结构、视觉关系和不确定性。

因此，正确结果不能只看“有没有生成 Markdown 文件”或“抽出了多少文字”，而要分别判断指定范围是否完整覆盖、正文是否连续可读、内容和结构是否保真、复杂视觉是否有去向、静态资源是否可携带、Unknown 和失败是否真实可见。来源隔离仍然重要，但它是保证端到端结果可信的约束，不是项目的首要业务价值。

## 先判断这五件事

如果下面五句话不正确，应先修改本文件，而不是修改 Workflow、Skill 或代码：

1. 用户指定的页或完整文档范围必须端到端转换，不能用局部结果、摘要或文件外壳代替。
2. 文字、数字、章节、层级、分区、列表、表格、公式、代码和可确认关系必须尽量保留并保持连贯。
3. 复杂视觉既要可搜索，也要在授权允许时保留必要的静态核对依据，不能被扁平 OCR 或摘要替代。
4. Markdown 与正文引用的静态图片必须组成可复制、可移动、脱离临时工程目录仍可使用的结果包。
5. 当前来源边界、Unknown、冲突、未覆盖和处理失败必须如实显示。

R01—R11 是上述方向的展开。它们是业务要求草稿，不是实现步骤，也不是已经通过的验收结论。

## R01 指定文档范围必须完整转换并形成可用结果

- 用户指定的页码范围或完整文档范围必须形成连续结果；每个应处理的页面或内容单元都要有明确去向。
- 结果不能漏页、重复、错序或混入未请求范围；部分页面成功不能外推为整份文档已经完成。
- 转换不能停在文件外壳、页面图片集合、散乱识别文字、摘要或工程中间产物；必须形成读者能够直接使用的 Markdown 结果包。
- 页面显示异常、局部解析失败或复杂视觉存在，不能成为静默丢弃其他有效内容的理由；已确认内容继续保留，失败范围单独标明。

不得把“生成了一个 Markdown 文件”或“部分页面有输出”当作完整转换。

## R02 Markdown 必须内容连贯、结构清楚并可独立使用

- 结果不是只有扩展名的文件外壳、固定字段集合、摘要或散乱 OCR 文字。
- 不要求每份来源都有相同字段、相同章节或相同页面结构；来源没有的内容不创建占位，不用模板补齐。
- 每个页面或内容单元只表达来源实际存在的部分，并按实际内容选择标题、段落、列表、表格、代码块或其他适合的 Markdown 结构。
- 跨页章节、段落和内容单元要按来源顺序连贯组织；读者不应为了恢复基本语义而重新拼接散乱页面或依赖原始编辑软件。
- “独立可用”要求主要内容能够直接阅读和搜索、结构关系有表达、必要静态资源链接可用，不等于只要 OCR 有文字就自然可读。
- 有可确认语义标题时，标题只表达内容主题；源文件名、页码、哈希和内部对象定位不能占据标题前缀。
- 没有可确认标题时，可以使用临时页码标题，但必须同时表明待复核状态。

## R03 文字、数字和文档结构必须尽量保留

- 文字、数字、章节、标题层级、分区、段落、列表、表格、公式和代码都属于转换对象。
- 多栏、卡片、侧栏、脚注、公式、代码和跨页连续内容应按实际结构表达，不能全部压成普通段落。
- 来源页面存在文字消失、错位、遮挡或渲染异常时，要保留能够确认的内容和异常边界，不能把异常当成来源没有内容。
- 无法可靠识别的局部内容要保留缺失范围和不确定性。

## R04 可确认的关系必须得到表达

- 流程、顺序、递进、包含、并列、对比、循环、层级、时间及其他可确认关系，应使用适合当前内容的列表、缩进、表格或关系说明表达。
- Markdown 表达只记录来源能够支持的关系，不为追求完整而补造箭头、因果、矩阵、层级或颜色含义。
- 关系证据不足时，只写已知部分，并明确标记 Unknown 或待复核。

## R05 复杂视觉必须同时可搜索、可核对

- 本要求受 U-B02 的保存与发布授权边界约束；当前不能自行假定所有来源都允许随结果保存原图或截图。
- 流程图、图表、漏斗、矩阵、时间线、树状图、关系网络、坐标图、统计图、仪表盘、地图、复杂公式排版和信息图等复杂内容，必须具有可搜索的 Markdown 表达；在 U-B02 允许时，同时随附必要静态视觉依据。
- Markdown 保存能够确认的标题、标签、图例、数值和关系，供阅读与搜索。
- 静态视觉依据保存空间、方向、层级、颜色编码、图例、数值对应和整体组织，供人工核对。
- Markdown 与视觉依据承担不同职责：前者支持阅读和搜索，后者保存不能被文字等价替代的视觉结构，任何一方都不能冒充另一方已经完成。
- 已经生成列表、表格、关系说明或其他结构化重述，不构成删除复杂视觉依据的理由。
- 扁平识别文字、摘要、列表、表格或其他结构化重述都不能单独证明复杂视觉关系已经保真；授权允许时，不能只留图片而不提供可搜索内容，也不能只留文字而失去原始视觉关系。

## R06 简单文字内容不保留无价值截图

- 纯文字、普通列表、简单表格或只承载简单文字的图片，在文字、数字、顺序和含义都已可靠表达且没有待核对关系时，只保留 Markdown。
- 是否保留文档内图片取决于语义和复核价值，不取决于承载文档是 PDF 还是 PPTX。独立图片只有在 U-B01 经人工确认纳入后才适用本规则。
- 转换过程中用于识别或检查的临时页面渲染，不自动成为读者资产。
- 仅仅识别出了图片中的文字，不足以删除仍承载空间关系的复杂视觉。
- 照片或扫描图中已经可靠转写、且不再承担布局、方向、图形或复核作用的文字区域，可以从随附图片中裁掉；仍有视觉作用的部分必须保留，不能因为文字已进入 Markdown 就整张删除。

## R07 必要视觉依据必须完整且最小充分

- 只有在 U-B02 确认允许保存和交付时，视觉依据才可以进入读者结果；权限不足时的替代交付或拒绝边界仍待人工决定。
- 优先保留能够完整承载语义的最小区域；全页布局、跨区域关系或必要上下文无法由单一区域表达时，保留整页。
- 区域图不能裁掉标题、图例、坐标轴、单位、箭头起止点、注释或理解所需的上下文。
- 裁切照片或扫描图时，只去掉已经由 Markdown 可靠承载且没有额外视觉价值的区域；裁切后的图片仍要保留理解关键关系所需的上下文。
- 整页图和区域图只有在各自承担不可替代的核对作用时才同时保留。
- 正文实际使用的视觉依据必须被引用，并说明用于补充或核对什么；未引用的工程中间图不进入读者结果。
- 视觉依据仍不足以确认内容时，不能通过裁剪或排版制造确定性。

## R08 Markdown 与必要资产必须便于阅读和携带

- 在 U-B02 允许交付视觉资产的前提下，Markdown 和正文实际引用的必要图片必须能够一起移动，作为一个交付整体使用，不能依赖原工作目录、临时绝对路径或外部文件继续存在。
- 正文只使用包内相对链接引用静态图片；复制、移动或解压整个结果包后，链接仍应可用。
- 结果包必须以最终读者内容为中心，不能要求读者从工程缓存、页面渲染目录、模型响应或临时预览中拼出正式文档。
- 读者首先看到语义内容；来源文件名、页码、哈希和内部对象定位保存在独立追溯信息中。
- 读者看到的图片名称应简短、稳定、可理解；具体命名和重名处理方式由后续设计确定。
- 交付结果不能包含大量未被正文引用的页面渲染或工程中间资产。

## R09 Unknown、冲突和失败必须如实保留

- 无法确认的文字、数字、层级、方向、颜色、关系和内容范围必须明确标记。
- 来源之间或提取结果之间发生冲突时，不静默选择任意一方；保留冲突、各自依据和需要人判断的事项。
- 结果要区分已确认、待复核、无法确认和失败范围，不能用一个“已转换”总词掩盖差异。
- 工具不可用、传输失败或解析失败不能伪装成内容已确认。
- 技术步骤成功不能单独证明内容正确；具体 Evidence、Verdict 和独立性规则由项目治理文件说明。
- 内容完整性、来源纯净、视觉关系、Unknown 和来源边界必须分别核对；局部成功不能外推到整份文档或全部来源。

## R10 当前来源必须隔离，多个来源默认分别转换

- 新结果中的标题、正文、数字、章节、结构和关系只能来自当前指定来源中能够确认的内容。
- 旧示例、历史输出、固定提示词、固定模板、上一份材料和其他来源不能进入当前结果；当前来源没有给出的内容不补写。
- 每个来源默认形成只讲自身内容的独立结果。
- 文件名相同、后缀不同、内容相似或目录相邻，都不能自动建立候选关系。
- 只有用户明确声明多个来源属于同一逻辑文档的候选版本时才比较。
- 候选比较必须保留每个来源、文字与结构差异、视觉差异、冲突和未决项；不得自动合并、自动选主版本或让一个来源覆盖另一个。

## R11 只允许不改变原意的轻度整理

- 可以修正转换过程中产生的明显识别错误、断行、段落、标题层级、列表和表格问题，使 Markdown 恢复来源原意并更易读。
- 来源文档本身存在的疑似错字、矛盾或异常不能静默改写；应保留原文，必要时标记待复核。
- 整理不得改变原意、结论、条件、范围、语气、因果和知识边界。
- 不允许摘要、扩写、删减、翻译、合并不同来源或加入来源之外的解释。
- AI 后加的结构说明不能冒充来源原文或原文总结。

## 退役编号

**R12 已退役且不得复用。** 它原来表示知识库低价值页清洗；最新人工纠正明确本项目只负责转换成 Markdown，因此 R12 不再是活跃需求。
